# packages/web/server/default-config/

## Responsibility
Default server-scaffolded OpenCode configuration and bundled agent role templates shipped for fresh runtime setup.

## Canonical asset boundary
- This directory is the sole source for distributable orchestration defaults. `lib/opencode/default-config-assets.js` inventories only root `opencode.json`, `agents/**`, runtime plugin files in `plugins/**`, and sanitized `user-profile/**`.
- Never ship auth, credentials, secrets, logs, caches, backups, lockfiles, generated manifests, `node_modules`, or test/spec/declaration files. Source-adjacent test fixtures are intentionally excluded from packaged assets.
- Clean-user profile provisioning is conflict-tracked and managed-runtime-only. Project runtime overlays separately copy/register plugins and preserve source-owned local plugin collision behavior; external runtimes are not mutated.

## Design
- `opencode.json` defines baseline agent/plugin constraints for embedded runtime startup. Every DevRyan-managed plugin registration is a relative path into the provisioned profile or a bundled local file; normal OpenCode startup never resolves a package or Git spec.
- `agents/*.md` provides canned role instructions (builder/fixer/orchestrator/etc.) copied or referenced during bootstrap flows. Every packaged child-capable specialist explicitly denies provider-native `task` and `devryan_task`, executes its assigned scope directly, and remains a leaf under the root-owned managed scheduler. Orchestrator owns design planning, including the grounded visual/UX approach in Plan Mode; Designer receives only an approved plan or decision-complete brief, then owns implementation, design-specific component tests, and visible validation. Fixer owns bounded non-design implementation, including frontend correctness with no visual judgment, and blocks before making design decisions. Mixed work uses disjoint ownership, with coupled UI/design files staying with Designer during implementation. Explorer reads only exact supplied/discovered paths and performs one bounded rediscovery after ENOENT. Builder, Fixer, and Orchestrator do not retry any `ctx_*` tool for the rest of the turn after one context-mode SQLite, disk I/O, or database-is-locked failure, fall back to safe native discovery, never replay potentially mutating commands, and keep test execution to one bounded command/group per `ctx_execute` call instead of synchronous whole-matrix loops. Builder/Fixer reread narrow patch hunks; Orchestrator treats specialist evidence as navigational, rereads every live target hunk before direct patching, delegates non-tiny multi-file remediation before Oracle, owns all remediation after the final Oracle review, and permits only one rebuilt retry after a context mismatch. Oracle defaults to a focused, read-only, high-reasoning review with explicit 30-tool exploration and five-finding limits. Orchestrator permits at most one optional late Oracle checkpoint per phase: immediately before a complex plan is presented, then separately after implementation delegation and initial validation. Review depth is chosen before that sole dispatch; a same-dispatch recovery remains the same logical checkpoint. After plan review, Orchestrator alone incorporates findings and presents the plan, with ordinary delegation reopening for later implementation. After final implementation/task review, Orchestrator dispatches no more specialists and directly remediates, revalidates, and finishes.
- Model-facing specialist result contracts use Markdown headings and a final Markdown status line. They never ask providers to emit XML-like report wrappers that can be misparsed as tool calls; the UI retains read-only formatting compatibility for historical XML results.
- Fixer assignments are closed work units: exact owned files, symbols, failing tests, or one cohesive root-cause cluster, plus explicit acceptance checks and exclusions. Open-ended repair backlogs remain parent-owned. Orchestrator dispatches at most three disjoint implementation children per wave, carries undispatched and newly discovered failures into later waves, and never expands an active Fixer through validation fallout. Fixer blocks before editing an unbounded assignment and reports unrelated verification failures as deferred work.
- `plugins/devryan-tool-input-guard.mjs` rejects missing/non-string `read.path`, multi-target `grep.path` strings, and parse-invalid JavaScript `ctx_execute` snippets with `DEVRYAN_TOOL_INPUT_INVALID`. It also makes shell execution deadlines explicit: `bash`/`shell` default to four minutes and accept integer overrides from one second through sixty minutes. It validates without executing, splitting, or repairing commands.
- Packaged Orchestrator recovery guidance treats ripgrep record limits, policy/workspace denials, and browser/web target misses as expected outcomes that require a narrowed path, in-scope source, refreshed state, or changed target before one retry. Failed commands and tests remain visible in the turn and diagnostic journal.
- `plugins/*.js` / `plugins/*.mjs` provides bundled OpenCode plugins copied into the active managed runtime config overlay. `devryan-managed-orchestration.mjs` exposes one scoped multi-action tool backed by DevRyan's private scheduler host, enforces 60-minute Fixer and Oracle deadline floors before submission and on explicit recovery overrides, and keeps one model-facing wait attached while repeating 25-second private polling slices only until the requested task is terminal. It returns `manualRecoveryRequired` immediately for provider-limit results and resumable failures after the single agent retry while leaving their envelopes pending for explicit Model Recovery, then derives an exactly-once idle-root continuation from durable retry-in-place lineage after user recovery. Parked Model Recovery results are omitted from that idle scan and do not inject a parent notice. Before injecting a collected-result wake it revalidates that the task is still terminal and unacknowledged. A missing task reference becomes the no-op `stale_task_reference` state only after a healthy root snapshot and clear authoritative barrier; retained acknowledged envelopes become `already_dispositioned`, while warnings, unavailable ownership, malformed responses, and current barrier tasks remain fail-closed. Successful dispositions evict their process-local collected-result entries. It also recovers pre-execution start registrations at the authoritative `session.idle` boundary and compacts matching terminal payload fields out of the task copy before serializing parent-model tool output; the authoritative result envelope remains complete. `devryan-browser.mjs` exposes a single session-turn-scoped `devryan_browser` tool only when Electron supplies the private discovery URL, bearer, and pinned binary. It canonicalizes OpenCode's rotating assistant-step message IDs to the parent user-message turn before acquiring, so sequential browser commands reuse one lease and daemon. Turn lookup and lease acquisition retry once only for network/502/503/504 failures; page-driving commands are never replayed, and stable `DEVRYAN_BROWSER_*` codes identify failures. It forces namespace/session/empty-config identity plus the 0.33.2 global `--idle-timeout 2m` option from a safe managed cwd, admits only reviewed page-driving commands (excluding the inspector server), single-flights first connection per reuse scope, bounds settled connection state with LRU eviction, strips credentials from the daemon environment, caps time/output, honors abort, and releases only its own lease on `close`. `devryan-builder-todo-continuation.mjs` resumes a successfully settled Builder turn on the same model when authoritative todos still contain pending work, coalesces duplicate idle edges, and stops after bounded stagnant attempts so a premature 3/N response is not terminal. `devryan-file-write-metadata.mjs` records whether an `oc_write` target existed before execution so shared UI can distinguish creates from edits without filesystem heuristics. `openai-gpt-5-6-models.mjs` pins Codex OAuth GPT-5.3 Spark and GPT-5.4/5.5/5.6 effective context plus auto-compaction thresholds, translating them through OpenCode's resolved reservation without changing API-key catalogs; it also defaults advertised reasoning options and variants from `reasoningSummary: "auto"` to `"detailed"` and enforces `"detailed"` again at request time. `devryan-oh-my-opencode-slim.mjs` is the DevRyan-preserving wrapper for `oh-my-opencode-slim` and intentionally strips Slim agent prompt/system-transform ownership while preserving Slim runtime hooks.
- `plugins/devryan-document-reader.mjs` removes non-image binary parts from provider-visible history, extracts bounded CSV/text, searchable PDF, DOCX, and safe ZIP content in resource-limited workers, caches only extracted text per task, and exposes session/verified-ancestor-scoped `devryan_document` list/read/search actions.
- `plugins/devryan-skill-context.mjs` tells the native `skill` tool to reuse a completed same-name skill while its full result remains in the active transcript, including across plan-to-implementation turns. It also directs `skill` and `ctx_execute_file` to route supporting skill files outside the active project through native `read`, whose per-agent external-directory grants remain authoritative; it forbids global OpenCode/Claude host allow rules and leaves Context Mode containment unchanged. Its provider-bound message transform keeps the first full body for each exact same-name/content version, replaces only later byte-identical repeats with deterministic reuse markers, retains changed versions and later returns to older versions as real transitions, and ignores compacted results as authoritative copies. The transform replaces request-local tool parts only, so canonical session history and journal evidence remain truthful. Managed web/Electron and VS Code overlays copy and register it; legacy Tauri assets intentionally remain frozen without it.
- Plan-safe managed routing resolves the exact parent turn before model selection. If the in-flight assistant is not visible yet, it accepts only the immediately preceding ordered assistant sibling when every persisted assistant since the latest user points to that same user; missing, newer, cross-turn, or conflicting records fail closed before private RPC. Designer returns `MANAGED_READ_ONLY_AGENT_UNSUPPORTED` before private RPC because it is implementation-only. Any other Cursor-configured read-only specialist uses the verified non-Cursor parent execution first, then the configured non-Cursor Plan agent, and reports the substitution in the tool result; no compatible fallback returns `MANAGED_READ_ONLY_PROVIDER_UNSUPPORTED` before private RPC.
- `user-profile/` is the sanitized, repository-owned clean-user baseline. It declares approved plugins through installed-local paths and preinstalls the exact reviewed Antigravity (`1.6.0`), Open Cursor (`2.5.4`), Claude proxy (`1.6.18`), Context Mode (`1.0.169`), Meridian (`1.57.0`), and Slim (`2.0.5`) dependencies. It ships Slim presets without MCP fields and does not bundle third-party skills. The Superpowers adapter registers an optional installed bundle for on-demand loading without injecting its bootstrap body into requests; a missing bundle produces only a non-fatal warning. The Slim loader remains strict about its provisioned local package. Neither adapter uses a bare-import, package-resolution, or network fallback. The OpenAI tool schema sanitizer remains a packaged runtime file copied and registered by managed overlays. The profile contains no auth material, generated state, lockfiles, or machine-specific paths.
- The managed `user-profile/` pins the document reader's `@opencode-ai/plugin@1.17.11`, `adm-zip@0.6.0`, `mammoth@1.12.1`, and `unpdf@1.8.0` runtime dependencies; legacy Tauri assets intentionally remain frozen without this feature.
- `.gitignore` keeps generated/localized artifacts out of source control.

## Flow
1. Server bootstrap checks for user/project config presence.
2. Missing config is initialized from this directory defaults.
3. Agent templates become available to orchestration tooling as default personas; only Orchestrator can call `devryan_task` directly.
4. Bundled plugins become available as runtime tools for managed OpenCode launches.
5. Managed startup provisions missing clean-user files and dependencies into `~/.config/opencode` while preserving user-modified managed files through a hash manifest.

## Integration
- Used by web server initialization paths that provision OpenCode-compatible defaults.
- Influences out-of-box behavior of agent execution, plugin loading, and prompt-role availability.
- Council fanout uses the managed bridge when injected so its children share the same durable lifecycle and unbounded immediate admission; the direct path remains only when no managed bridge exists.
