# packages/web/server/default-config/

## Responsibility
Default server-scaffolded OpenCode configuration and bundled agent role templates shipped for fresh runtime setup.

## Canonical asset boundary
- This directory is the sole source for distributable orchestration defaults. `lib/opencode/default-config-assets.js` inventories only root `opencode.json`, `agents/**`, runtime plugin files in `plugins/**`, and sanitized `user-profile/**`.
- Never ship auth, credentials, secrets, logs, caches, backups, lockfiles, generated manifests, `node_modules`, or test/spec/declaration files. Source-adjacent test fixtures are intentionally excluded from packaged assets.
- Clean-user profile provisioning is conflict-tracked and managed-runtime-only. Project runtime overlays separately copy/register plugins and preserve source-owned local plugin collision behavior; external runtimes are not mutated.

## Design
- `opencode.json` defines baseline agent/plugin constraints for embedded runtime startup. Every DevRyan-managed plugin registration is a relative path into the provisioned profile or a bundled local file; normal OpenCode startup never resolves a package or Git spec.
- `agents/*.md` provides canned role instructions (builder/fixer/orchestrator/etc.) copied or referenced during bootstrap flows. Oracle defaults to a focused, read-only, high-reasoning review with explicit 30-tool exploration and five-finding limits; deep review must be requested explicitly and permits up to 80 tools. Orchestrator gates Oracle routing to high-risk correctness boundaries and supplies exact scope, critical invariants, existing validation evidence, and exclusions so Oracle does not repeat tests or silently widen the review.
- `plugins/*.js` / `plugins/*.mjs` provides bundled OpenCode plugins copied into the active managed runtime config overlay. `devryan-managed-orchestration.mjs` exposes one scoped multi-action tool backed by DevRyan's private scheduler host, enforces the Oracle 60-minute deadline floor before submission, and keeps one model-facing wait attached while repeating 25-second private polling slices so live snapshots stay internal and only a terminal result returns. It leaves both provider-limit results and resumable failures after the single agent retry pending for explicit Model Recovery, and derives an exactly-once idle-root continuation from durable retry-in-place lineage when an external timeout detached the original wait. It also recovers pre-execution start registrations at the authoritative `session.idle` boundary and compacts matching terminal payload fields out of the task copy before serializing parent-model tool output; the authoritative result envelope remains complete. `devryan-browser.mjs` exposes a single session-turn-scoped `devryan_browser` tool only when Electron supplies the private discovery URL, bearer, and pinned binary. It canonicalizes OpenCode's rotating assistant-step message IDs to the parent user-message turn before acquiring, so sequential browser commands reuse one lease and daemon. It forces namespace/session/empty-config identity plus the 0.33.2 global `--idle-timeout 2m` option from a safe managed cwd, admits only reviewed page-driving commands (excluding the inspector server), single-flights first connection per reuse scope, bounds settled connection state with LRU eviction, strips credentials from the daemon environment, caps time/output, honors abort, and releases only its own lease on `close`. `devryan-builder-todo-continuation.mjs` resumes a successfully settled Builder turn on the same model when authoritative todos still contain pending work, coalesces duplicate idle edges, and stops after bounded stagnant attempts so a premature 3/N response is not terminal. `devryan-file-write-metadata.mjs` records whether an `oc_write` target existed before execution so shared UI can distinguish creates from edits without filesystem heuristics. `openai-gpt-5-6-models.mjs` pins Codex OAuth GPT-5.3 Spark and GPT-5.4/5.5/5.6 effective context plus auto-compaction thresholds, translating them through OpenCode's resolved reservation without changing API-key catalogs; it also defaults advertised reasoning options and variants from `reasoningSummary: "auto"` to `"detailed"` and enforces `"detailed"` again at request time. `devryan-oh-my-opencode-slim.mjs` is the DevRyan-preserving wrapper for `oh-my-opencode-slim` and intentionally strips Slim agent prompt/system-transform ownership while preserving Slim runtime hooks.
- `user-profile/` is the sanitized, repository-owned clean-user baseline. It declares approved plugins through installed-local paths and preinstalls the exact reviewed Antigravity (`1.6.0`), Open Cursor (`2.5.4`), Claude proxy (`1.6.18`), Context Mode (`1.0.169`), Meridian (`1.57.0`), and Slim (`2.0.5`) dependencies. It ships Slim presets without MCP fields and does not bundle third-party skills. The Superpowers adapter is registered for compatibility but remains inert with a non-fatal warning until its optional user-installed bootstrap exists; the Slim loader remains strict about its provisioned local package. Neither adapter uses a bare-import, package-resolution, or network fallback. The OpenAI tool schema sanitizer remains a packaged runtime file copied and registered by managed overlays. The profile contains no auth material, generated state, lockfiles, or machine-specific paths.
- `.gitignore` keeps generated/localized artifacts out of source control.

## Flow
1. Server bootstrap checks for user/project config presence.
2. Missing config is initialized from this directory defaults.
3. Agent templates become available to orchestration tooling as default personas; only Orchestrator can call `devryan_task` directly.
4. Bundled plugins become available as runtime tools for managed OpenCode launches.
5. Managed startup provisions missing clean-user files and dependencies into `~/.config/opencode` while preserving user-modified managed files through a hash manifest.

## Integration
- Used by web server initialization paths that provision OpenCode-compatible defaults.
- Influences out-of-box behavior of agent execution, plugin loading, and prompt-role availability.
- Council fanout uses the managed bridge when injected so its children share the same durable lifecycle and unbounded immediate admission; the direct path remains only when no managed bridge exists.
