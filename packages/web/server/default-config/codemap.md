# packages/web/server/default-config/

## Responsibility
Default server-scaffolded OpenCode configuration and bundled agent role templates shipped for fresh runtime setup.

## Canonical asset boundary
- This directory is the sole source for distributable orchestration defaults. `lib/opencode/default-config-assets.js` inventories only root `opencode.json`, `agents/**`, runtime plugin files in `plugins/**`, and sanitized `user-profile/**`.
- Never ship auth, credentials, secrets, logs, caches, backups, lockfiles, generated manifests, `node_modules`, or test/spec/declaration files. Source-adjacent test fixtures are intentionally excluded from packaged assets.
- Clean-user profile provisioning is conflict-tracked and managed-runtime-only. Project runtime overlays separately copy/register plugins and preserve source-owned local plugin collision behavior; external runtimes are not mutated.

## Design

- `plugins/devryan-session-changes.mjs` records managed execution boundaries through the private host bridge. Known read-only tools and task/Council wrappers are excluded; shell/MCP and native file tools are included. Terminal canonical events finish captures when failed/cancelled tools bypass the after hook. External runtimes without the bridge receive no injected capture behavior.


- `plugins/devryan-openai-oauth.mjs` installs the managed OpenAI transport through the config hook without replacing the provider's OAuth login methods. It fetches only access credentials from the private host bridge or Bot run gateway before each provider call and prepares access-only image auth. No global fetch patch, credential tool, arbitrary target proxy or refresh-token copy is introduced. The same source is copied into the Bot image.

- **Safe browser inspection**: `plugins/devryan-browser.mjs` validates `inspect` selectors and requested CSS/attribute names before acquiring a lease, then queries and reads in one synchronous page evaluation. Missing and ambiguous matches return explicit observations without reading an arbitrary element. Invalid CSS selectors remain input errors; generated-script failures remain runtime errors. Only explicitly framed caller `eval` TypeError/ReferenceError/SyntaxError exceptions use `DEVRYAN_BROWSER_EVAL_ERROR`. Tests cover lease reuse, sanitization, bounded output, and error separation; the isolated Electron acceptance runner lives at `packages/electron/tests/browser-inspection/run.mjs`.

- Managed runtime overlays add the resolved DevRyan data root (`OPENCHAMBER_DATA_DIR`, otherwise `~/.config/openchamber`) plus POSIX `/tmp` and canonical real-path variants to the external-directory allowlist for agents that already declare permissions. This does not widen their read, edit, or tool permissions.
- `opencode.json` defines baseline agent/plugin constraints for embedded runtime startup. Every DevRyan-managed plugin registration is a relative path into the provisioned profile or a bundled local file; normal OpenCode startup never resolves a package or Git spec.
- `agents/*.md` provides canned role instructions (builder/fixer/orchestrator/etc.) copied or referenced during bootstrap flows. Every packaged child-capable specialist explicitly denies provider-native `task` and `devryan_task`, executes its assigned scope directly, and remains a leaf under the root-owned managed scheduler. Orchestrator owns design planning, including the grounded visual/UX approach in Plan Mode; Designer receives only an approved plan or decision-complete brief, then owns implementation, design-specific component tests, and visible validation. Fixer owns bounded non-design implementation, including frontend correctness with no visual judgment, and blocks before making design decisions. Mixed work uses disjoint ownership, with coupled UI/design files staying with Designer during implementation. Explorer reads only exact supplied/discovered paths and performs one bounded rediscovery after ENOENT. Builder, Fixer, and Orchestrator do not retry any `ctx_*` tool for the rest of the turn after one context-mode SQLite, disk I/O, or database-is-locked failure, fall back to safe native discovery, never replay potentially mutating commands, and keep test execution to one bounded command/group per `ctx_execute` call instead of synchronous whole-matrix loops. Builder/Fixer reread narrow patch hunks; Orchestrator treats specialist evidence as navigational, rereads every live target hunk before direct patching, delegates non-tiny multi-file remediation before Oracle, owns all remediation after the final Oracle review, and permits only one rebuilt retry after a context mismatch. Oracle defaults to a focused, read-only, high-reasoning review with a 15-minute, 20-inspection, three-finding ceiling; explicitly deep reviews use 30 minutes, 50 inspections, and five findings. Orchestrator permits at most one optional late Oracle checkpoint per phase: immediately before a complex plan is presented, then separately after implementation delegation and initial validation. Review depth is chosen before that sole dispatch; a same-dispatch recovery remains the same logical checkpoint. After plan review, Orchestrator alone incorporates findings and presents the plan, with ordinary delegation reopening for later implementation. After final implementation/task review, Orchestrator dispatches no more specialists and directly remediates, revalidates, and finishes.
- Context Mode routing is role-specific: broad, multi-file, derived, aggregated, or unpredictably sized analysis defaults to Context Mode, while bounded exact lookups and edit hunks stay native. Explorer receives project indexing/search, Librarian receives web indexing/search, Plan permits only verified project indexing plus search/stats/web indexing, and writable roles retain execution tools. Every role falls back to bounded native tools without retrying after one storage failure.
- Model-facing specialist result contracts use Markdown headings and a final Markdown status line. They never ask providers to emit XML-like report wrappers that can be misparsed as tool calls; the UI retains read-only formatting compatibility for historical XML results.
- Fixer assignments are closed work units: exact owned files, symbols, failing tests, or one cohesive root-cause cluster, plus explicit acceptance checks and exclusions. Open-ended repair backlogs remain parent-owned. Orchestrator dispatches at most three disjoint implementation children per wave, carries undispatched and newly discovered failures into later waves, and never expands an active Fixer through validation fallout. Fixer blocks before editing an unbounded assignment and reports unrelated verification failures as deferred work.
- `plugins/devryan-tool-input-guard.mjs` rejects missing/non-string native read paths, blocks known binary paths for both `read` and `oc_read`, removes unexpected binary read output before persistence, and scrubs historical binary read results only from provider-bound request copies. It preserves textual formats and proper image attachment parts while returning stable bounded guidance instead of raw bytes. The same plugin rejects multi-target `grep.path` strings and parse-invalid JavaScript `ctx_execute` snippets with `DEVRYAN_TOOL_INPUT_INVALID`, and makes `bash`/`shell` deadlines explicit from one second through sixty minutes. Its path guard (`validateToolPathInput`) runs first for `read`/`oc_read`, `edit`/`multiedit`/`patch`/`write`, `grep`/`glob`/`list`, and `bash`/`shell` `cwd`/`workdir`: degenerate absolute paths (over 512 characters, over 40 segments, a segment over 255 bytes, a segment repeated four times, `//` after a non-existent prefix) and outside-project paths under a directory that does not exist fail with `DEVRYAN_TOOL_INPUT_INVALID` before OpenCode's `external_directory` prompt; relative paths, in-project paths, existing external directories, and writes whose external parent exists pass through.
- Packaged Orchestrator recovery guidance treats ripgrep record limits, policy/workspace denials, and browser/web target misses as expected outcomes that require a narrowed path, in-scope source, refreshed state, or changed target before one retry. Failed commands and tests remain visible in the turn and diagnostic journal.
- `plugins/*.js` / `plugins/*.mjs` provides bundled OpenCode plugins copied into the active managed runtime config overlay. `devryan-managed-orchestration.mjs` exposes exactly one loader-visible factory and one scoped multi-action tool backed by DevRyan's private scheduler host, enforces a 15-minute focused Oracle default, a 30-minute explicit deep Oracle window, 60-minute Designer/Fixer floors, and a 30-minute ordinary-specialist floor before submission and on explicit recovery overrides, and keeps one model-facing wait attached while repeating 25-second private polling slices only until the requested task is terminal. It returns `manualRecoveryRequired` immediately for provider-limit results and resumable failures after the single agent retry while leaving their envelopes pending for explicit Model Recovery, then derives an exactly-once idle-root continuation from durable retry-in-place lineage after user recovery. Parked Model Recovery results are omitted from that idle scan and do not inject a parent notice. Before injecting a collected-result wake it revalidates that the task is still terminal and unacknowledged, then acquires the scheduler's atomic 60-second task claim; prompt failures release the claim for a later scan. A missing task reference becomes the no-op `stale_task_reference` state only after a healthy root snapshot and clear authoritative barrier; retained acknowledged envelopes become `already_dispositioned`, while warnings, unavailable ownership, malformed responses, and current barrier tasks remain fail-closed. Successful dispositions evict their process-local collected-result entries. It also recovers pre-execution start registrations at the authoritative `session.idle` boundary and compacts matching terminal payload fields out of the task copy before serializing parent-model tool output; the authoritative result envelope remains complete. `devryan-browser.mjs` exposes a single session-turn-scoped `devryan_browser` tool only when Electron supplies the private discovery URL, bearer, and pinned binary. It canonicalizes OpenCode's rotating assistant-step message IDs to the parent user-message turn before acquiring, so sequential browser commands reuse one lease and daemon. An `open` command with no URL uses the lease's redacted active-branch preview URL; when none exists, it releases a newly created lease and returns successful guidance to retry with the discovered local loopback URL without connecting or assuming a port. Explicit URLs are otherwise unchanged, and `branch_preview_auth_failed` remains distinct from generic lease transport failures. Turn lookup and lease acquisition retry once only for network/502/503/504 failures; page-driving commands are never replayed, and stable `DEVRYAN_BROWSER_*` codes identify failures. It forces namespace/session/empty-config identity plus the 0.33.2 global `--idle-timeout 2m` option from a safe managed cwd, admits only reviewed page-driving commands (excluding the inspector server), single-flights first connection per reuse scope, bounds settled connection state with LRU eviction, strips credentials from the daemon environment, caps time/output, honors abort, and releases only its own lease on `close`. `devryan-builder-todo-continuation.mjs` resumes a successfully settled Builder turn on the same model when authoritative todos still contain pending work, coalesces duplicate idle edges, and stops after bounded stagnant attempts so a premature 3/N response is not terminal. `devryan-file-write-metadata.mjs` records whether an `oc_write` target existed before execution so shared UI can distinguish creates from edits without filesystem heuristics. `openai-gpt-5-6-models.mjs` pins Codex OAuth GPT-5.4/5.5/5.6 official context windows with a 256,000-token auto-compaction threshold, preserves GPT-5.3 Spark's smaller limits, and translates thresholds through OpenCode's resolved reservation without changing API-key catalogs; it also defaults advertised reasoning options and variants from `reasoningSummary: "auto"` to `"detailed"` and enforces `"detailed"` again at request time. `devryan-oh-my-opencode-slim.mjs` is the DevRyan-preserving wrapper for `oh-my-opencode-slim` and intentionally strips Slim agent prompt/system-transform ownership while preserving Slim runtime hooks.
- Managed result delivery defaults the packaged `devryan_task` model-facing `submit`, `status`, `wait`, `cancel`, and acknowledgement calls to private reference mode. Matching previews above 8,192 UTF-8 bytes expose an initial `resultReference`; `read_result` accepts only the exact process-local next cursor, advances it only after a valid page, and never acknowledges or removes the collected result. Exact `DEVRYAN_MANAGED_RESULT_MODE=eager` omits `resultMode` and preserves the previous serialization as a one-release rollback override; changing the override requires restarting managed OpenCode. Internal recovery scans, Council, UI routes, older plugins, and legacy Tauri assets remain eager.
- `plugins/devryan-document-reader.mjs` removes non-image binary parts from provider-visible history, extracts bounded CSV/text, searchable PDF, DOCX, and safe ZIP content in resource-limited workers, caches only extracted text per task, and exposes session/verified-ancestor-scoped `devryan_document` list/read/search actions.
- `plugins/devryan-skill-context.mjs` preserves same-session skill reuse and external-reference safety. Its request-local system transform also compacts Anthropic and Grok skill catalogs without removing names or on-demand bodies; paths, repeated boilerplate, and description overflow do not enter those provider prompts.
- Plan-safe managed routing resolves the exact parent turn before model selection. If the in-flight assistant is not visible yet, it accepts only the immediately preceding ordered assistant sibling when every persisted assistant since the latest user points to that same user; missing, newer, cross-turn, or conflicting records fail closed before private RPC. Designer returns `MANAGED_READ_ONLY_AGENT_UNSUPPORTED` before private RPC because it is implementation-only. Any other Cursor-configured read-only specialist uses the verified non-Cursor parent execution first, then the configured non-Cursor Plan agent, and reports the substitution in the tool result; no compatible fallback returns `MANAGED_READ_ONLY_PROVIDER_UNSUPPORTED` before private RPC.
- `user-profile/` is the sanitized, repository-owned clean-user baseline. It declares approved plugins through installed-local paths and preinstalls the exact reviewed Antigravity (`1.6.0`), Open Cursor (`2.5.4`), Claude proxy (`1.8.0`), GPT Image Generation (`0.1.10`), Context Mode (`1.0.169`), Meridian (`1.62.6`), and Slim (`2.2.15`) dependencies. The Claude tuple holds Agent SDK `0.2.141` and Claude Code `2.1.215`; this satisfies Meridian's `^2.1.198` runtime contract so stateful resume usage and lineage are not run against an unsupported older binary. GPT Image Generation exposes `gpt_imagegen` through the existing ChatGPT OAuth credential surface; it does not add or package credentials. The profile ships Slim presets without MCP fields and does not bundle third-party skills. The Superpowers adapter registers an optional installed bundle for on-demand loading without injecting its bootstrap body into requests; a missing bundle produces only a non-fatal warning. The Slim loader remains strict about its provisioned local package. Neither adapter uses a bare-import, package-resolution, or network fallback. The OpenAI tool schema sanitizer remains a packaged runtime file copied and registered by managed overlays. The profile contains no auth material, generated state, lockfiles, or machine-specific paths.
- The managed `user-profile/` pins the document reader's `@opencode-ai/plugin@1.18.27`, `adm-zip@0.6.0`, `mammoth@1.12.1`, and `unpdf@1.8.0` runtime dependencies; legacy Tauri assets intentionally remain frozen without this feature.
- `.gitignore` keeps generated/localized artifacts out of source control.

## Flow
1. Server bootstrap checks for user/project config presence.
2. Missing config is initialized from this directory defaults.
3. Agent templates become available to orchestration tooling as default personas; only Orchestrator can call `devryan_task` directly.
4. Bundled plugins become available as runtime tools for managed OpenCode launches.
5. Managed startup provisions missing clean-user files and dependencies into `~/.config/opencode` while preserving user-modified managed files through a hash manifest.

## Integration
- Used by web server initialization paths that provision OpenCode-compatible defaults.
- Influences out-of-box behavior of agent execution, plugin loading, and prompt-role availability.
- Council fanout uses the managed bridge when injected so its children share the same durable lifecycle and unbounded immediate admission; the direct path remains only when no managed bridge exists.
- `plugins/devryan-primary-recovery.mjs`: versioned host handshake, model-step admission and read-only pre-execution fencing. The older plugin SDK does not expose health; the host verifies `/global/health`.
