# packages/web/server/lib/browser-cdp/

## Responsibility
Browser control and observation boundary: private desktop-only, session-turn-scoped lease control plus a separate principal-authenticated, view-only projection for managed browser owners.

## Design
- The bridge itself lives in the Electron main process (`packages/electron/browser-cdp-bridge.mjs`); this module owns server-side lease identity, OpenCode lineage scope, and private HTTP authorization.
- Status and the expected bearer token arrive as injected callbacks from the Electron host, never from `process.env` reads: the OpenCode child copies env once at spawn and cannot observe later parent mutations, so the token is minted at Electron startup and passed to the child at spawn while the live ws URL is fetched through this route.
- Deny-by-default: loopback peer required (checked via `req.socket.remoteAddress`, not proxy-supplied headers, because the app sets `trust proxy`), bearer required, no caching, no permissive CORS. Web/remote runtimes supply no callbacks, so the route 404s.
- The private capability routes register after the bounded common JSON parser but before the generic UI `/api` authentication middleware. Managed OpenCode has no browser cookie; its loopback peer, bearer, and lease scope are the complete machine-to-machine authorization boundary, while ordinary UI APIs remain principal-authenticated.
- `observation-runtime.js` registers only after managed UI authentication. It projects an allowlist of labels and attachment state from server lease records, filters every request by exact managed principal, Browser policy, current root-session ownership, and assignment, and never exposes host paths, OpenCode IDs, surface IDs, navigation URLs, cookies, Access credentials, or CDP capabilities. Administrators receive no cross-owner bypass.
- Observation views are one-time, short-attach sessions with one active view per principal/lease. Their same-origin multipart JPEG responses are `no-store`, `no-transform`, and proxy-buffering-disabled; access is revalidated while streaming and every viewer is aborted on disconnect, revocation, ownership/lease loss, replacement, or shutdown. Frames remain owned by the Electron stream and are never persisted or included in audit metadata.
- Responses use deterministic states — `disabled`, `no_target`, `debugger_conflict`, `ready` — so an agent can branch without parsing prose. A ws URL is only ever emitted for `ready`.
- `lease-runtime.js` resolves child-to-root session lineage from OpenCode with a bounded, directory-aware 100-entry session-lifetime parent LRU and per-node singleflight, serializes exact `opencodeSessionID + messageID` acquisition, and fences stale host callbacks. Successful lineage survives transient OpenCode outages until session deletion or managed-runtime reset; unseen nodes retry only network/timeout/5xx failures twice, while authoritative missing/mismatched/cyclic/depth-invalid lineage fails immediately without fallback. It checks injected host availability before both reuse and creation so a disabled host deterministically returns `agent_browser_disabled` and retires any stale reusable record. Electron's missing-owner race maps to `browser_owner_context_unavailable`, distinct from a generic `browser_host_unavailable` failure.
- Lease scope is `{ rootSessionId, opencodeSessionID, messageID, directory, agent }`. Reuse, touch, and release require the exact normalized current-session turn, directory, and agent. In managed mode, an injected resolver adds authoritative owner/project/branch plus redacted preview URL/origin/status metadata after lineage resolution. Preview credentials travel only in the one create callback and are never stored in the lease record or returned by snapshots. `session.idle`, `session.deleted`, and `session.error` release only leases owned by that exact OpenCode session.

## Flow
1. The bundled `devryan_browser` tool POSTs `/api/desktop/browser-leases` with its authoritative tool context and managed bearer.
2. The runtime validates peer + bearer, resolves the root session, reuses the exact turn lease when present, resolves any assigned branch preview on first use, and asks Electron to create a guest otherwise. A failed Access probe returns `branch_preview_auth_failed` before a login loop can open.
3. `open` without a URL selects the assigned preview. An explicit loopback HTTP(S) URL replaces only its origin with the assigned preview origin, preserving path, query, and fragment; explicit public URLs remain unchanged.
4. The tool touches the lease around each command and DELETEs it on explicit `close`; a `close` immediately following failed acquisition is idempotent and does not repeat the failed probe. Authoritative session lifecycle events, managed OpenCode process replacement, and graceful shutdown are fallback cleanup. Managed replacement increments the admission epoch, aborts and drains old-epoch lineage/acquisition work, releases every old lease, holds admission closed while the child is replaced, and resumes only after replacement completes (including the failure path).
5. `/api/desktop/browser-cdp` remains the validated managed discovery anchor used to derive the private server origin; its scalar bridge status is compatibility-only.
6. The managed web UI reads `GET /api/browser/agent-leases`, refetches after its principal-filtered SSE lifecycle event, and creates/deletes an ephemeral `/views` session only while its selected lease tab is active. The public server relays the Electron multipart stream without sharing the private control capability.

## Integration
- Registered by `server/index.js` through the base-route bootstrap's private-capability hook so UI authentication cannot intercept the managed bearer.
- Electron injects create/touch/release callbacks; standalone web and VS Code omit them and receive 404.
- App-bound Electron injects observation snapshot/stream callbacks directly. Runtime-service mode reaches the foreground Electron host through its authenticated desktop-host broker; an absent or older host fails the view only and never disturbs the lease.
- `packages/web/server/default-config/plugins/devryan-browser.mjs` is the only managed model-facing lease client.
