# packages/web/server/lib/opencode/

## Responsibility
Core OpenCode integration layer: config entities (agents/commands/skills/providers/mcp), auth/session state, route registration, process/network bootstrap, and lifecycle management.

## Design

- Cursor runtime status preserves its platform capability. Unsupported hosts
  return that status before provider credential authorization; warming and
  verification routes retain the runtime's typed 503 refusal.

- **Native candidate host** (`runtime-host/`) embeds the pinned SDK under
  mandatory admission and execution gates, using the existing Node ledger
  and scheduler through their private bridge. See
  [runtime-host/codemap.md](runtime-host/codemap.md) for module ownership and
  the current acceptance/parity boundary.

- **Native application client** (`opencode-client/`, `v2/`, `opencode-client-seam.js`)
  keeps the existing application wire contract behind the v2 runtime. The public
  client and helper seam require an explicit generation-2 identity on every call;
  missing, legacy and unknown identities fail before I/O. SDK wire types and
  `toV1` projection names remain application compatibility vocabulary. The v2
  route policy, projections, admission boundary and semantic-loss register are
  documented in [v2/codemap.md](v2/codemap.md). Public requests and privileged
  admission share one runtime snapshot; an epoch change rejects further work
  instead of replaying it against another runtime. Recovery and session-change
  hosts receive this same client from server composition. Native execution is
  still gated separately by the integrated host acceptance.
- Private image/context attachment reads use `privileged.readCanonicalUserPage`:
  the existing native sequence page and message projector retain only IDs whose
  original native type is `user`. Standalone notices remain visible in the UI
  without becoming attachment authority. The same raw page separately seals
  the latest non-status native turn parent and its exact record fingerprint;
  shell/compaction continuations can anchor context without becoming attachments.
  The current context must include that canonical anchor, and inactive historical
  attachments are excluded before worker processing. Genuine user parts retain their original
  synthetic flags. Every raw row and byte counts toward the host's 2,000-row /
  64-MiB history bound; cursor cycles refuse before more history is consumed.
- **Observed runtime identity** (`lifecycle.js`, `runtime-selection.js`,
  `core-routes.js`, server `index.js` and `hmr-state-runtime.js`) carries the
  managed child's actual home/config/state/data/database paths and advances the
  epoch when their owner changes. `/health` exposes an opaque
  `openCode.runtimeIdentity`; UI observations invalidate cached capabilities on
  replacement, including same-URL restarts. There is no external or PATH-discovered runtime launch. The entrypoint first binds
  a verified generation-2 bundle; this launch observation is separate from its atomic selector.
  Lifecycle starts only that native owner, waits for its catalog, drains the exact child
  on replacement, and refuses inherited HMR process readiness without current native ownership.
  The application lifecycle facade forwards the verified version into the same
  module state used by health, runtime resolution and HMR persistence; readiness
  and bound-port guards remain independent of version reporting.

- `execution-artifacts.js` separately content-pins the bundled browser adapter for a per-call browser capability. It remains subject to native process confinement; only the declarative orchestration adapters receive control-tool execution. See `../browser-cdp/codemap.md`.

- `session-scoped-revert.js` owns route-local query/body validation, disconnect cancellation and bounded diagnostics. Mutations require the injected native coordinator; no generic HTTP or OpenCode snapshot restoration path exists. `session-revert-coordinator.js` binds conversation-only native stage/clear to the exact durable mutation transaction through the admission owner. `session-execution-host.js` supplies canonical reads, confined execution and target cancellation. Imported receipt history remains inspectable, but pre-capture edits without a native mutation transaction cannot be undone or redone. See `docs/CONCURRENT_REVERT.md`. `session-provider-spawn.js`
  and `session-provider-worker.mjs` own the confined Claude transport. On Windows the worker verifies its launcher before constructing the native private file owner for protected state/provider directories, and the execution host forwards its existing owner to all read-only helpers;
  `claude-credential-projection.js` projects the account's current Claude access
  token into it (the sandbox cannot read the keychain). The transport runs in,
  and keys its private state by, the requesting session directory: the
  `devryan-claude-transport.mjs` plugin sends it to the loopback proxy as
  `x-devryan-directory`, and `resolveSessionWorkingDirectory` refuses (400) a
  bounded request without a verifiable one instead of using the OpenCode
  process cwd. The pinned
  companion change and generated clients live under `companion/`.
- `runtime-restart-reconcile.js` settles sessions left busy by a crashed managed
  OpenCode once its replacement reports them idle; `lifecycle.js` reports every
  managed exit (with a bounded stderr tail) and restarts on a crash immediately.

- `imagegen-model-hotfix.js` owns the exact-source GPT-6 Astra / medium image request patch, applied during managed profile provisioning and copied into the Bot image build. Unknown or partial source changes block startup/build; unrelated model defaults remain owned by their existing configuration.

`env-runtime.js` retains bounded shell-environment and Git executable discovery. OpenCode runtime discovery, WSL/PATH launch and installers are removed. `opencode-resolution-runtime.js` reports only the verified native bundle controller and its manifest version; missing identity fails closed.
- **Creation outcomes and timing** (`session-creation.js`) defines safe restart rejection versus unknown outcome and records content-free attempt timing before managed routes intercept the proxy. `lifecycle.js` records recent probes separately from startup readiness; busy-process preservation remains authoritative.
- **Barrel API** (`index.js`) re-exports domain operations for server composition.
- **Runtime factories** (`*-runtime.js`) isolate IO-heavy behaviors (network, startup, watcher, shutdown).
  Ordinary shutdown stops the shared global event hub after native settlement and watcher shutdown, before store teardown, so its upstream reconnect timer cannot retain a stopped web or Electron host. A refused native settlement keeps that hub alive for the existing shutdown retry.
- **Agent runtime settings** (`agent-runtime-settings.js`, `config-entity-routes.js`, `lifecycle.js`) retain desired switches in the sidecar and compare them with the last successful managed launch snapshot. Saves never rewrite a running overlay. A launch captures one snapshot before preparation and records it only after readiness; external or unknown application stays explicit in GET and PUT responses.
- **Packaged prompts** (`packaged-agent-sync.js`, `lifecycle.js`, `config-entity-routes.js`) preserve edits by default. Host-admin configuration status bypasses the manifest fast path and never writes. Explicit restoration requires the inspected content hash, serializes with startup sync, moves the observed regular single-link file into a durable backup, verifies identity and content, and publishes without overwriting a racing replacement. Refused restores preserve both edits; successful changes queue through the existing configuration-apply owner. There is no checkpoint export in these routes.
- **Shared OpenAI OAuth** (`openai-oauth-coordinator.js`, `openai-oauth-bridge.js`, `chatgpt-siwc.js`, `chatgpt-siwc-enrollment.js`, `chatgpt-siwc-host.js`, `openai-model-availability.js`, `openai-siwc-model-catalog.js`) owns signed Sign in with ChatGPT enrollment, opaque returning registrations, recoverable staging and selected-credential comparison (including verified SDK first-record autoactivation and already-active staged recovery), native owner sign-out/drain with remote/local outcomes, single-flight refresh against `auth.openai.com/api/accounts/oauth/token`, selected-native SIWC account model catalog annotation preserving account order/names and refusing failed/stale lookups, generation-checked persistence, managed auth mutation admission and private access-only delivery. `default-config/plugins/devryan-openai-oauth.mjs` supplies the managed host/Bot transport to `api.openai.com` Responses; see `docs/BOT_OAUTH_COORDINATION.md`.
  Native credential commits own this shared queue through complete reverse-action settlement. HTTP response lifetime does not hold a second queue span: nesting it around the native commit would deadlock. Cursor API-key saves join the existing native integration facade, preserving the separate usage-token vault; legacy `auth.json` is not a native credential owner.
- **Scoped Bot auth boundary** (`auth.js`) can project exactly one host provider
  into a private per-run file and ingest only that provider; graceful shutdown
  stops the Bots runtime before ordinary OpenCode/server teardown.
- **Route split by concern** (`core-routes.js`, `openchamber-routes.js`, `skill-routes.js`, `provider-routes` patterns).
- **Shared JSON body parsing** (`core-routes.js` `resolveSharedJsonBodyLimit`) parses only listed `/api` prefixes so the OpenCode proxy can stream the rest; `api-json-body-coverage.test.js` scans every server route registration and fails when an `/api` route reads `req.body` without an inline parser or a listed prefix.
- **Config scope model** in shared helpers (`shared.js`) for user/project/global entity resolution.
- **Provider integration aliases** (`provider-integrations.js`, `github-copilot-models.js`) normalize DevRyan-managed provider ids such as GitHub Copilot across upstream payloads, auth files, config-source checks, and account-specific model discovery fallbacks; all-false modern picker payloads are narrowed to GitHub's utility-model contract instead of exposing unverified rows.
- **Claude authentication and plugin policy** (`claude-cli-runtime.js`, `claude-auth-status.js`, `anthropic-oauth-plugin.js`, `providers.js`) resolves explicit, managed-profile, and effective-PATH Claude executables once for auth and quota parity, uses the official non-billable auth-status command, strips private account metadata, recognizes versioned proxy specs, upgrades DevRyan's legacy bare spec to the reviewed release, and preserves explicit user pins.
- **Exclusive title ownership** (`standard-session-title-runtime.js`, `session-title-outbox.js`, `cursor-session-title-runtime.js`, `runtime-agent-overlays.js`) disables OpenCode's built-in title agent in managed runtime overlays. Standard titles request the session's exact provider, model and variant (from the prompt, else the first user message), which the native owner requires to admit the title helper; they retain the prompt preview until one selected-model result (30-second admitted-generator budget, or final local fallback after retry exhaustion/permanent provider rejection) is ready, durably enqueue before projection, and use authoritative-idle PATCH/read verification. Generic managed-child placeholders require matching canonical parent/agent identity and summarize the brief after known initial runtime prefixes. Startup/reconnect/watchdog recovery visits loaded placeholders with bounded concurrency; custom titles remain authoritative. Title helpers share provider-error classification with `session-model-text.js`: explicit errors bypass repair, permanent rejection settles locally, and transient errors retain bounded generation retries. Cursor retains its separate path and a bounded cache of generated-but-unsaved titles. A failed metadata read/PATCH retries projection without another model request; changed source text/project and manual renames invalidate retained results. Cursor title generation passes the session identity for separate `cursor.title.usage` journal observations.
- **OpenCode Slim adapter** (`slim-config.js` + `agents.js`) reads `oh-my-opencode-slim` config/presets, composes those model defaults with Slim-installed global `agents/*.md` prompt files, exposes Slim-managed agents to Settings, and writes Slim agent model/variant overrides back to the Slim config instead of DevRyan's sidecar. Slim keeps the coordinator model/variant, while explicit saved Council member overrides retain their independent order and efforts through both raw-Slim and wrapper agent read paths. Native snapshots consume that same member metadata instead of a stale companion; missing overrides retain companion selections, and explicit empty arrays remain empty. Normalized `modelRefs` and `councillors` are not provider request fields.
- **Legacy Cursor migration** (`legacy-cursor-plugin.js`) runs before managed profile writes. It recognizes the audited bundle by SHA-256 in both discovery directories, and it recognizes open-cursor's default installer symlink by its package entrypoint (any version) or audited target bytes. It creates verified `.disabled` byte backups or `.link.json` link records outside discovery, removes only matching local registrations, unlinks symlinks without touching their targets, and resumes after interruption. Unknown or modified copies never block OpenCode: provisioning reports a `profileNotices` entry, `/health` exposes it as `openCodeProfileNotices`, and the UI offers `POST /api/config/legacy-cursor-plugin/retire` (administrator only). That route moves the confirmed copies to backups and restarts OpenCode through the idle-aware apply coordinator. The maintained Cursor adapter remains the single owner.
- **Retired plugin cleanup** (`managed-plugins.js` + `user-profile-provisioning.js`) removes plugin registrations DevRyan no longer ships (`cursor-acp`, Context Mode) and drops a retired profile dependency only at the exact version DevRyan pinned; user-owned versions and leftover data directories are untouched.
- **Managed Meridian prompt policy** (`user-profile-provisioning.js` + `meridian-sdk-features.js`) gives locally managed OpenCode a combined Claude Code/client prompt baseline, migrates the previously owned client-only baseline, and exposes an explicit persistent Claude-only compatibility mode. User choices release field ownership, unrelated Meridian settings remain untouched, and configured external runtimes stay read-only.
- **Meridian HTTP cancellation compatibility** (`meridian-http-hotfix.js`, `meridian-http-server.js`, `user-profile-provisioning.js`) validates the exact managed Meridian source and uses native Bun request signals where the bundled Node adapter loses disconnects. Node behavior, request/SDK cancellation, queue guards, and graceful/forced shutdown remain covered independently. The same gate replaces Meridian's working-directory resolution with the requesting session directory (see the confined Claude transport above); previous complete installations upgrade in place.
- **Managed runtime overlays** (`runtime-agent-overlays.js`, `runtime-surface-policy.js`, `worktree-permissions.js`) generate high-precedence OpenCode config directories so user-side agent model defaults, skill visibility, active-project worktree-container access, allowlisted plugins, blocked ambient MCP tombstones, and runtime-only user remote MCP timeout guards apply at execution time without editing project/package agent markdown or persisted MCP config. Executable agent frontmatter contains only OpenCode-supported scalar model fields; DevRyan `modelRefs`/`councillors` metadata is stripped, while ordered Council models are reconciled atomically through the version-1 `agents/council.models.json` companion. Source-configured local plugins are not restated in the overlay, and a same-named packaged plugin registration remains dormant until the source entry disappears, preventing duplicate plugin hooks/tool schemas.
- **Account execution overlay** (`lifecycle.js` plus the managed-orchestration
  plugin/private RPC) resolves sparse managed-account agent defaults by durable
  root-session owner at dispatch time. It remains separate from the generated
  host runtime overlay, so personal defaults never edit or apply host OpenCode
  configuration and Council remains host-managed.
- **Plugin read model** (`plugins-readonly.js`) exposes configured entries and both singular `plugin/` and plural `plugins/` user/project files to Settings without mutating runtime configuration.
- **Harness diagnostics and proactive warmup** (`harness-result.js`, `harness-preflight.js`, `config-credential-scan.js`, `harness-tool-manifest.js`, `harness-run-fingerprint.js`, `turn-timing.js`, `agent-runtime-warmup.js`, `project-prewarm-runtime.js`, `xai-tool-catalog-runtime.js`) expose timing/preflight evidence and populate a bounded Grok catalog cache outside prompt dispatch. Shared model refreshes own a 20-second deadline; caller cancellation only ends that caller's wait. Runtime disposal cancels owned reads, fences late writes, and permanently stops periodic refresh. Fingerprints distinguish configured plugin identities from observed factory loads, hash effective roles/catalogs/policies and retain unknown evidence. Missing or unequal evidence preserves the full tool surface.
- **Task/project context adapter** (`harness-task-context.js`) reads bounded canonical sessions, real-user anchors, native project identity and scoped managed state for the shared task-context store. It serves the existing private bridge, forwards the child compaction envelope's remaining encoded byte budget, and keeps global/non-Git projects directory-scoped. Its independent `harness_plan` handler resolves the selected revision through `../plans/selected-revision.js`, checks the authoritative root agent and canonical running `devryan_task` call, and rechecks objective, generation and owner before updates commit. Compaction reads that same current revision; plan tools grant no general filesystem access. `authorizePrivateRpc` rereads canonical root session and current primary role before model delegation, collection and context actions; Builder's enabled task tool permits only selected-plan actions, while internal recovery/compaction and trusted host/UI actions keep their existing paths.
- **Provider-only context contract**: proxied and streamed assistant messages retain OpenCode's provider token payload unchanged. Shared UI selects the newest token-bearing assistant message and derives both occupancy and capacity from that message's provider/model/variant; this module does not estimate or enrich prompt/tool/message source categories.
- **Global behavior ownership** (`global-agents-md-runtime.js`, `global-agents-md-routes.js`) treats `~/.config/opencode/AGENTS.md` as the sole prompt source, keeps external runtimes read-only, and reports refresh failures without hiding successful persistence.
- **Revisioned configuration apply** (`config-apply-runtime.js` + `@openchamber/shared-runtime`) batches exact mutation scopes, waits for authoritative idle state or performs an administrator-authorized forced restart, retains concurrent revisions across in-flight work, and requires explicit acknowledgement for externally owned runtimes.
- **Bundled runtime metadata** (`opencode-resolution-runtime.js`) reports only the verified native bundle. The standalone OpenCode update endpoint is retired; runtime updates arrive through DevRyan updates. `opencode-update-check.js` serves the click-driven `GET /api/config/opencode-update-check` latest-upstream lookup (fixed npm registry URL, stable 2.x only, stable 503 codes). `opencode-update-runtime.js` retains only pure historical version identity normalization for offline QA.
- **Managed serve log level** (`lifecycle.js`) launches `opencode serve` with `--log-level` on both the direct and WSL argument lists (default `WARN`; `DEVRYAN_OPENCODE_LOG_LEVEL` accepts `DEBUG`/`INFO`/`WARN`/`ERROR` case-insensitively, anything else falls back to `WARN`) so the managed `opencode.log` stays small.
- **Diff bodies never leave the server** (`diff-summary.js`, `v2/facade-routes.js`, `routes.js`): message-list and session responses keep per-file counts but drop patch text. The shared native hub applies `stripEventDiffContent` before replay/fan-out. Both SSE and WebSocket clients receive this projected stream; no raw upstream SSE pass-through remains.
- **OpenCode database maintenance** (`db-maintenance-core.js`, `db-maintenance.js`, `db-maintenance-worker.js`, `db-maintenance-routes.js`): read-only inspection and dry runs for the Settings OpenCode Storage block. The retained v1 core is a schema-guarded, time-bounded, delete-only pass over OpenCode 1's durable `event` table (events of deleted sessions, and old events of idle sessions down to the newest 64 seqs; `event_sequence` untouched so seq continuity holds; VACUUM only with free disk ≥ 1.2× the file and no other OpenCode process alive), run in a worker thread, with results persisted to `opencode-db-maintenance.json` and the harness journal. It mutates only when the selected runtime is generation 1, and runtime selection accepts generation 2 only, so DevRyan never runs a mutating pass: the pre-launch hook (`beforeManagedSpawn`, which the native lifecycle never called) and the forced-compaction hand-off were removed, and `POST /api/storage/opencode-db/compact` serves only `{ dryRun: true }` (`409 maintenance_not_applicable` otherwise, with no restart). A native v2 database inspects as `v2_database` (maintenance not needed, Dry Run off), because v2 keeps no event log to trim and the v1 orphan rule would drop live v2 sessions' `event_sequence` rows. `opencodeDbMaintenance.{idleHours,keepSeqPerAggregate}` in settings.json tune the dry run; `enabled` gated only the removed pre-launch pass and has no effect.
- **Durable project icons** (`project-icon-store.js`, `project-icon-routes.js`) keep uploaded image bytes and a self-describing atomic manifest under the runtime data directory. Settings metadata is a reconciled projection, so manifest-backed icons survive settings rewrites and deterministic project-ID migration across desktop app replacement.

## Flow
1. Server bootstrap resolves env/config (`env-config`, `settings-normalization-runtime`).
2. Startup pipeline creates OpenCode process/network/session runtimes.
3. Route registrars expose config/auth/control APIs and verified bundled runtime metadata to UI and CLI.
4. Watchers + event handlers update session/auth/theme state and drive downstream SSE/WS notifications.

## Integration
- Primary dependency of `packages/web/server/index.js`.
- Integrates with `ui-auth`, `event-stream`, `skills-catalog`, `tunnels`, and filesystem/project modules.
- Contract provider for UI settings/auth/config editors and CLI automation paths.
- Global agent behavior is absent by default and stored only at `~/.config/opencode/AGENTS.md`; clearing it removes the file.

- **Passthrough session handoff**: `meridian-passthrough-hotfix.js` supplies reversible pinned-bundle edits; `meridian-passthrough-handoff.js` settles complete tool boundaries and verifies native checkpoints after narrowly classified SDK exits. Checkpoint resumes fork the selected native branch so older denied-tool records cannot replace actual client results. Passthrough disables mutable native Git snapshots and implicit background status inference, and stops processing at forwarded hooks. Ordinary continuations, explicit undo/fork and cancellation keep their existing contracts. The managed `meridian-http-hotfix.js` gate upgrades complete prior revisions and rejects partial edits. Reproduction and disk/history tradeoffs: `docs/audits/2026-09-07-claude-quota.md`.
- **Default thinking display metadata**: `model-default-thinking.js` enriches the `routes.js` provider catalog without modifying model options or send configuration.

- `watcher.js` retains the authoritative SSE/hub envelope directory when invoking canonical side effects, so terminal tool receipts reach session-change capture with validated directory scope.

- Managed plugin upgrades and preservation gates: [upgrade runbook](../../../../../docs/PLUGIN_UPGRADES.md). `meridian-upgrade-patches.js` holds the source-gated 1.68.0 candidate port; it does not promote the selected Claude tuple.

- `session-execution-host.js` applies the shared admission budget to private companion requests and journals summarized `session_execution` records (slow or failed requests, slow or failed phases); finish/publication retains its native settlement contract.
- `session-execution-host.js` also answers `direct-admit`/`direct-finish` for the built-in read, glob, grep and skill (`DEVRYAN_DIRECT_CONTROL_RECEIPTS=0` makes the companion use leases). A read-only direct finish records only the fenced ledger commit, with no session-change attestation (`DEVRYAN_DIRECT_LEDGER_ONLY=0` restores it), and journals a `direct_finish` step summary when slow, and `warmLedger` runs one cancellable background ledger build per host when a project opens (`agent-runtime-warmup.js`, `project-prewarm-runtime.js`; `DEVRYAN_LEDGER_PREWARM=0`).
- `session-execution-host.js` runs the controller's reviewed Git helpers (`execution-helper-policy.js`) only with a working directory inside a registered helper root, and sets `GIT_CEILING_DIRECTORIES` to the parent of the outermost registered root that owns it. A registered folder nested in an unregistered repository is therefore not a work tree to the controller (it never learns, then asks to run in, that refused parent root); a registered repository root keeps discovery for itself and registered folders below it.
- `session-execution-host.js` journals one `finish` summary per control or process call (slow or failed only, like a direct finish): `tool_execution` is the run time between claim and finish, followed by `termination_receipt`, `publication`, `execution_receipt` and `change_receipt`. The published call's private view is removed after the result is returned (`lease_cleanup` with `deferred: true`; shutdown waits for removals in flight; `DEVRYAN_DEFERRED_LEASE_CLEANUP=0`). A control tool that is read-only for session changes records no attestation (`DEVRYAN_CONTROL_LEDGER_ONLY=0`). A cancelled confined call records an empty confined receipt, because its view was discarded and it changed nothing (`DEVRYAN_CANCELLED_RECEIPTS=0`). Each confined process call is registered with the idle watchdog from launch to finish.
- `runtime-selection.js` owns `opencode-runtime-selection.json` in the DevRyan data directory (next to `managed-opencode-processes.json`): which OpenCode runtime (generation, companion/plain/host kind, binary, channel) and which data directory, database and config directory it uses. `application.js` writes it atomically once at server boot from the selected native bundle (generation 2, kind `host`, the bundle's `launch.opencodeDatabasePath`); only generation 2 records are accepted. A record describes the runtime launched by the server named in `ownerPid`: readers in any other process treat it as absent.
- `db-maintenance.js` acts on the selected database and passes its runtime generation to `db-maintenance-core.js`. Without a selection, mutating runs are skipped (`runtime_selection_unavailable`, persisted and journaled); inspection and dry runs fall back to the legacy guess and report `dbSource`. The core mutates only for `runtimeGeneration: 1` and positively refuses a v2 database (`v2_database`: any `kv` table, where v2 records `migration.v1-v2`; v1 through 1.18.33 has none) on a read-only connection before the file is ever opened for writing; inspection reports `generation` (1 = a v1 `migration` or `__drizzle_migrations` journal plus `session_context_epoch`). Every 1.18.x database has a `migration` table, so that table is not a v2 signal.
- `opencode-db-path.js` retains read-only inspection of data directories that predate the manifest. Worktree metadata stays in the host project file; `git/service.js` never updates the retired generation-1 SQLite project table.
- `lifecycle.js` restarts a live, idle OpenCode after three consecutive failed health probes instead of one; a process that exited restarts at once and a busy one is still preserved (`DEVRYAN_HEALTH_RESTART_FAILURES=1` restores the single-failure restart).
- `opencode-routes.js` retains only the shared `opencode_route_unknown` denial payload. The pinned native `v2/route-policy.js` and typed browser facade own authorization; there is no live `/doc` registry, generic upstream proxy, or environment switch that restores legacy forwarding.

- `harness-duplicate-qualification.js` matches the runtime identity (the companion build identity from `companion.json`: upstream version, base commit, patch and build inputs; or an exact binary hash for legacy profiles), route, request-shaping policy vector and ordered plugin content inventory against release-owned acceptance profiles. Missing evidence leaves duplicate projection disabled; `harness-run-fingerprint.js` serves its existing private bridge and preserves the inventory separately from factory observations.
- `duplicate-provider-route.js` owns the host-attested authentication transport for a selected route: OpenAI ChatGPT OAuth through the OAuth coordinator and xAI OAuth from OpenCode's `xai` auth record type. Every other route, including Claude through Meridian, attests nothing and stays unqualified.
- `harness-duplicate-profiles.js` records the reviewed release defaults and live-evidence digest. Installation paths remain part of host/caller agreement; portable release matching uses ordered filenames/content hashes, the selected provider's full configuration and the host-attested authentication transport. API-key and unqualified routes remain inactive. The agent-browser 0.38.1 plugin change marks all six historical profiles stale without changing their evidence hashes; the default optimization stays off until matched live requalification.

## Paired execution and retention

`harness-task-context.js` also supplies `readCanonicalPlanIdentity` to HTTP
plan routes. It reads bounded session/source-assistant metadata through the
authorized storage root, validates message membership and project identity,
and derives session creation/slug rather than accepting a caller's filename
identity. Shared `selected-revision.js` containment rejects unrelated non-Git
directories that carry OpenCode's `global` project ID, while retaining literal
registered storage aliases and unambiguous legacy root/subdirectory selections.

- `execution-preparations.js` tracks original-identity preparing/ready/failure results, progress, polling ownership and cancellation; polls never dispatch a second tool. `execution-artifacts.js` requires artifacts from the supported manifest, with protocol and digest acceptance gates.
- `session-activity-gate.js` owns synchronous activity/tree holds and staged connected-client selections. `session-retention.js` selects only eligible, exclusive native subtrees and rechecks settings, selections, managed ownership and execution/recovery ledgers under its host hold. The native retention owner proves full-subtree quiet state inside original Inbox locks and the SQLite transaction, then atomically archives or transfers the exact root hold into existing durable removal. New activity produces a typed skip; automatic cleanup never cancels or stops work. There is no companion retention-control transport.
  Confined workers set HOME and the platform temporary-directory variables to their private scratch directory, including zsh's separate TMPPREFIX for heredocs. Temporary-file APIs therefore stay inside the lease; `DEVRYAN_SESSION_TMP` is the durable per-session location, and ignored output folders are written through on macOS (see `packages/harness-runtime/lib/execution-inputs.js`). The companion remaps only in-project absolute `apply_patch` file headers into the confined view, preserving literal file content and external-path enforcement. It normalizes transient synthetic prompt text into typed worker-local message/part identities before admission. It preserves the complete text, rejects malformed real/tool records, and never uses those transient identities as execution or collection evidence.
- `ssh-managed-identity.js` proves managed ownership and signs instance-bound shutdown requests; health responses alone never authorize credential installation or shutdown.

- `execution-artifacts.js` locates the bundled execution supervisor independently of the controller. `verifyExecutionArtifacts` seals only that writer-supervisor contract; `runtime-host/native-artifacts.js` verifies the complete native bundle. Production composition requires the generation-2 controller, writer and supervisor; missing artifacts refuse startup without a plain-runtime downgrade. Native confinement, capability and artifact digest checks remain mandatory.
- Preparation claim synchronously fences its poller timer before the durable claim. Abandonment and drain settle I/O before cancellation/cleanup; recovery isolates each lease and retries durable terminal cleanup while preserving uncertain writer protection.

`execution-preparations.js` authenticates protocol-2 polls against the admitted in-memory job’s complete session/message/call/token, tool, directory, execution kind and argument fingerprint. Polls bypass ledger reconciliation and identity HTTP lookups; durable generation, ownership and execution checks remain mandatory at claim. Poll waiting retains request response headroom. Preparation lifetime remains independent of each poll; cleanup failures retain the original preparation error and emit separate diagnostics.

The native constructor runs the audited built-in `skill` loader through direct receipts alongside `read`, `glob`, and `grep`; the host allowlist is in `session-execution-host.js`. Canonical sequence ownership, current permits and cancellation fences remain mandatory. The public companion execution bridge is unavailable.

- `selection-timing.js` traces only selection-request ingress, authenticated/middleware arrival, activity-gate entry/exit and response finish/close. Correlation uses an opaque request ID and validated numeric revision; logs exclude request bodies, credentials, session IDs and conversation content. The gate declaration supports the UI controller integration test against the real server revision fence.
