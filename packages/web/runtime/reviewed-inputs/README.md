# Reviewed runtime inputs

These are exact repository-owned captures of already selected package versions, retained with their package metadata and captured licenses. Production must use static compiled inputs or verified executable assets; it must never import their original `.cache` locations or mutable user `node_modules`.

The built-in agents (formerly the Oh My OpenCode Slim plugin) are no longer a captured input. They are owned source in `packages/agents-core`, derived from Slim v3.0.4 (`UPSTREAM.md`, MIT `NOTICE`), and compiled from the workspace. The authority seams that `rewriteReviewedSlimServer` used to apply at build time are direct source changes there: frozen per-location configuration, host log sinks, an owned hook factory and interview bridge, the host-verified AST worker asset, invocation-owned web fetch and path access, and no updater. `packages/agents-core/index.d.ts` is the declared surface the host compiles against. Tasks, Council, TODO/context, provider/permission ownership and browser/document/image execution retain their existing reviewed owners.

AST grep 0.45.3 includes the actual darwin-arm64 executable under a DevRyan asset name and captured package metadata/READMEs. Only the confined worker may bind it, after manifest verification; its process cwd must be the private workspace view. Other platform executables are unavailable. Both captured package manifests declare MIT, but this capture lacks a standalone AST license notice: this is an explicit release provenance gap, not a claim of complete distribution qualification.

The source manifest records every captured byte. Added declarations are DevRyan integration source, not claimed original package files. Dormant command/skill files remain present as data; their presence does not activate code or widen resource grants.

`model-catalog/` separately retains exact public model metadata and its retrieval provenance. It is data, outside the executable package-closure manifest. The native build embeds `DevRyan-model-catalog.json` as a file input and records its hash in the linked source inventory. The pinned SDK reads that embedded file with catalog fetching and snapshot fallback disabled; startup verifies the effective model and effort requirements per location.

JSDOM 30.1.1 is the exact pre-existing web fetch dependency captured in the repository spike. Its bounded DOM extraction build closure includes original package metadata/licenses, captured lock-integrity entries and exact dependency resolutions. The build embeds the original default stylesheet and seals the already-absent optional canvas export to null. The agents-core web fetch retains its original URL, redirect, llms probe, charset, body-limit, extraction, rendering, model-selection and cache algorithms; constructor-owned invocation callbacks provide actual fetch, grant-scoped cache, binary publication and supervised secondary provider authority. No global package lookup or raw user-data root is authorized.

The repository production document and browser modules are inventoried separately as hash-guarded inputs. Their parser/tool/rendering and browser validation/lease/sequence/inspection algorithms remain original. Native adapters delegate I/O to existing constructor owners; browser process callbacks must use the supervised private-browser worker and document parsing must settle under its existing worker owner. Exporting worker-only originals does not authorize controller spawn, ambient caches, arbitrary attachment reads, or bearer propagation.

Claude is not a captured input. OpenCode's claude-agent provider runs the user's own Claude Code through `@anthropic-ai/claude-agent-sdk`, a locked workspace dependency compiled into the controller; the host launches the user's `claude` (`runtime-host/claude-agent-host.js`).
