# packages/ui/src/components/chat/

## Responsibility
Implements the interactive chat surface: message timeline, composer/input, streaming status UI, permission/question blocking cards, and chat-specific navigation/scroll behavior.

## Design
- **Container + leaf split**: `ChatContainer.tsx` orchestrates state wiring, while specialized children (`MessageList`, `ChatInput`, `StatusRow*`, cards) handle focused rendering.
- **Provider-stall recovery**: `StatusRowContainer.tsx` projects a confirmed semantic tool-input stall as an explicit Stop & Retry action. The action refetches and rechecks the exact pending call before a confirmed abort. An exact initial blank inference shell is instead stopped automatically after the watchdog's final recheck. Both hand off to the existing `PrimaryModelRecovery` card, and neither resends automatically.
- **Long-running tool recovery**: the status row observes exact `ctx_execute`, MCP alias, `bash`, and `shell` calls without a live duration; after the sync watchdog confirms ten minutes without semantic progress, the actionable warning includes elapsed time and presents a user-controlled Stop action. The action performs a final exact-call resync before confirmed abort; completion wins the race, and no tool is retried or routed into model recovery.
- **Managed recovery projection**: `lib/turns/projectManagedTransportRecovery.ts` recognizes only the orchestration runtime's exact timeout/connection, active-resume, and task-authorized manual retry-in-place continuation records. It restores authoritative creation-time order when complete timestamps prove that mixed legacy Cursor and native OpenCode IDs inverted the transcript, removes internal continuation prompts from display, reparents recovered assistant siblings into the original visible turn, and annotates interrupted or aborted messages from the latest authoritative child-task plus narrow manual-recovery state as continuing, recovered, action-required, or stopped. Canonical messages and journal evidence remain unchanged; primary-session failures keep their normal actionable error rendering.
- **Performance-oriented memoization**: heavy/hot paths use `React.memo`, stable callbacks, and selector discipline to reduce render fanout during streaming.
- **Cold Markdown rendering**: `MarkdownRenderer.tsx` retains its lazy implementation and accepts an optional `loadingFallback`. Verified Bot rows use escaped final text until the rich renderer loads; other callers retain the existing fallback and startup chunk boundaries.
- **Completed assistant images**: `MessageList.tsx` projects one bounded candidate list only after every visible assistant sibling completes; the final `MessageBody.tsx` owns a recovery-aware lazy gallery after response content.
- **Local domain helpers**: `lib/`, `hooks/`, and focused helpers such as `chatInputDraftPersistence.ts` encapsulate turn navigation, timeline, blocking requests, composer persistence, and scroll/follow logic. Permanent session deletion synchronously retires a matching active composer target before the normal target-switch save, then releases that local retirement at the switch boundary.
- **Selection-to-composer ownership**: `lib/selectionMarkdown.ts` is the one DOM-selection-to-Markdown converter shared by the selection menu and the configurable Cmd/Ctrl+L action. `lib/sendSelectionToComposer.ts` accepts only non-editable selections inside the active chat message surface, appends a fenced `md` block, clears the browser selection, and focuses the visible composer without stealing terminal/dialog/form shortcuts.
- **Question-card ownership**: `QuestionCard.tsx` owns navigation and request lifecycle, `QuestionOptionRow.tsx` is the sole interactive owner for each option, and `questionCardSubmission.ts` provides session-scoped identities, an in-flight shadow map, acknowledgement reconciliation, answer/Skip submission, partial-failure retry filtering, and the duplicate-submit lock. Submit and Skip collapse immediately into a compact pending state; success clears acknowledged requests, while partial failure restores only failed requests with their answer state intact. Skip needs no selected answer, rejects every unresolved request represented by the card once, and never resends an acknowledged request.
- **Permission-card shell aliases**: `permissionCardPatterns.ts` owns the complete shell-tool predicate used by permission icons, names, specialized command rendering, and duplicate pattern filtering.
- **Managed-task dispatch projection**: `managedTaskDispatch.ts`, `ManagedTaskList.tsx`, `ManagedTaskRow.tsx`, and `managedTaskListWindow.ts` remove raw `devryan_task` calls from assistant content and render fresh starts or fresh-child retries in chronological, assistant-message-owned Agent Dispatch cards. Separate dispatching assistant messages keep separate cards, while parallel launches within one message share that message's card. Wait/barrier and same-child recovery messages never take ownership, later user turns remain separate, and exact task/part identity preserves launch order without adjacency or timing heuristics. A provisional start retains its OpenCode `callID`; if authoritative output arrives in a later message, the task row replaces `Preparing...` in the original dispatch card through the same `(rootSessionId, dispatchCallId)` rather than moving or duplicating the card. Once start output supplies a real task ID, its message-scoped fallback row subscribes to that exact task leaf and performs one delayed root-scoped snapshot immediately if the live event was missed; stale `starting` output therefore cannot remain after the durable task advances. Persisted wait output supplies the same exact-identity fallback after restart. When the shared sync layer receives the root session's authoritative idle event while a managed projection remains active, it performs one final root-scoped snapshot, covering a missed terminal SSE event and clearing every exact row plus the root barrier without inferring activity from historical tool output or creating a poller. `managedTaskCompactionProjection.ts` and `ManagedTaskCompactionContinuity.tsx` add one narrow exception: after a real compaction boundary, currently undispositioned task lineages that began before the latest boundary are repeated at the live bottom of the chat until disposition. Genuinely new post-compaction dispatches remain turn-local, and retry/resume descendants retain continuity through `priorTaskId` ancestry. Dispatch narration and reasoning retain their relative order above each message-owned card, but control-only wait/poll messages suppress internal reasoning so the root shows only the managed waiting status. Preparing starts render provisionally; terminal start failures remain in the same card with a concise sanitized error and no child action. Queued rows remain visibly queued without navigation; starting/running rows expose Open Subtask as soon as the canonical child session exists. Same-child resume/recovery lineages collapse to one logical row and link to the canonical child. An active manual retry uses ordinary queued/preparing/running copy; after success the row reports the selected model and thinking level in success styling. When the managed child itself has no semantic assistant activity to name, its status row uses the narrow latest-task leaf to show deterministic `Waiting for model` or `Recovering subtask` copy instead of a random generic working phrase.
- **Cursor-native dispatch observation**: `cursorNativeTaskDispatch.ts` and `CursorNativeTaskRows.tsx` recognize only the versioned runtime-owned projection on a Cursor parent `task` tool. `MessageBody.tsx` removes that one raw tool row and adds a clearly labelled `Cursor native · Observed` section to the same Agent Dispatch card, with expandable narration, bounded nested tool activity, provider steps, and terminal output. These rows deliberately expose no managed task ID, child-session link, retry, or cancel control and never enter the managed Zustand/scheduler projection.
- **Assistant output rhythm**: every assistant-timeline transition uses one responsive 8px mobile / 12px desktop gap. `MessageBody.tsx` owns that exterior gap across assistant text, reasoning, files, message actions, tool/skill groups, and the final Agent Dispatch card; `ProgressiveGroup.tsx` applies the same gap between the skill/tool rows it groups; `ChatMessage.tsx` applies it between sibling assistant messages in the same turn, covering provider-split output → skill and skill → output boundaries. Provider reasoning uses one adaptive `ReasoningGroup` per contiguous run in both render modes: active runs stay collapsed, completed singletons under 15 seconds or without trustworthy timing render inline, and long or multi-part runs stay collapsed. Its session-scoped mounted-active ownership suppresses only duplicate assistant-status thinking copy, leaving the bottom row's reserved space and controls intact. Child rows retain only their internal hit-area padding. The transcript tail drops inter-turn padding so `ChatContainer.tsx` can apply a deliberately larger 12px mobile / 16px desktop gap before the live status row after either a turn-owned Agent Dispatch card or a compaction-continuity card; completed turn boundaries keep their larger separation. The status row consumes a scalar managed-root phase: provisional/queued/starting dispatches say `Starting subagent delegation`, the first running child or an explicit wait/control call switches to `Waiting for subagent output`, and terminal unreviewed results remain waiting until disposition.
- **Manual model recovery**: `ModelRecoveryCard.tsx`, `PrimaryModelRecovery.tsx`, and `ControlledModelPicker.tsx` provide one Agent Dispatch-style recovery surface with locally controlled model and thinking-level selection for failed primary turns and resumable managed children. A first provider-limit failure closes its safe `agentRetryAvailable` policy flag and shows the embedded card immediately, even if the child still reports provider `retry` while cleanup settles. The exact Claude third-party-usage classifier error instead offers an explicit compatibility preflight: a Claude retry must persist Claude-only prompting before the existing manual resend, while selecting another provider skips the configuration change. An initial grouped hard deadline says that the Orchestrator retains one saved-progress recovery without mentioning Try Again; a final grouped hard deadline uses timeout-specific title/detail copy and remains terminal/actionable while the killed child tears down. The failed model and thinking remain preselected, but only an explicit Try Again sends `retry_in_place`; acknowledgement hides the card, and another failed manual attempt restores it on the same child lineage. Ungrouped and non-resumable deadlines use neutral terminal copy. `provider_prompt_rejected` is deliberately excluded: its row explains clean-context recovery while the scheduler requires a fresh child and a rewritten prompt.
- **Contract-aware message rendering**: message parts and tool activity rendering live under `message/parts/*` to map SDK part types to UI blocks. Managed `devryan_browser` calls intentionally suppress command-level presentation and use one generic `Using DevRyan Browser` activity label.
- **Derived plan revision projection**: canonical turn records produce a stable plan trace index. `PlanTurnTraceContext.ts`, `PlanTurnTraceProvider.tsx`, and `usePlanTurnTraceEntry.ts` expose only the current source/version/actionability leaves to plan cards, so superseded plans stay visible but cannot be implemented.
- **Plan persistence and opening**: sync lifecycle detection eagerly ensures the latest completed plan's revision-specific Markdown file even while its chat is unmounted. `PlanCard` consumes the saved pointer, retains missing-metadata fallback and explicit retry, gates implementation on the authoritative path, and sends only that path. Once the current actionable revision is saved, `StatusRow` atomically claims its one-time auto-reveal only on mobile/VS Code and opens the main Plan tab; desktop keeps the context panel closed until the user selects `View Plan`. Plan-mode message rendering treats the actionable Plan card as the terminal visible content block so late provider reasoning cannot displace it.
- **Plan-linked task progress**: saved-plan implementation prompts require one immutable todo per numbered plan task using the `Phase <number>: <task>` contract. `todoSummary.ts` parses only that explicit prefix, and `StatusRow` projects the active phase as `Phase n: Task x/y`, lists only that phase's stripped task titles, and advances from authoritative todo status; ordinary Builder todos retain their whole-list presentation. When `ChatInput` supplies `tabBackground`, `StatusRow` renders the active-session task/plan row as the tucked-behind-card "tab" bar that matches the draft project/branch bar: the task summary (`Task n/N: <summary>` for ordinary todos, `Phase n: Task x/y` for saved plans) sits on the left and expands the full task list on click, while the `Plan` action (plan icon plus label) sits on the right and hides while that list is expanded. `ChatInput` passes `suppressTab` while any message is queued so this strip yields the tucked tab to `QueuedMessageTab` without unmounting (plan auto-reveal / preload effects keep running, and an expanded task list collapses). The shared assistant-status `StatusRowContainer` omits `tabBackground` and keeps the flat layout.
- **Queued steering ownership**: `queuedSend.ts` owns atomic FIFO and exact-row claims, stable queue-item identity, per-item dispatch-time transport identity and Builder handoff authorization, captured session directory/model configuration, parent-correlated assistant-completion waits, rollback, and the send-now `steer → flush` boundary. `QueuedMessageTab` owns the composer strip while anything is queued: every queued message is a row in one tucked tab with explicit Steer / Send Now, edit, and remove actions; edit pops the exact row back to the composer. The queue tab suppresses the task/Plan bar. Steer still routes through `handleQueuedMessageSend` (`interruptCurrentOperationForQueuedSend` + `dispatchQueuedMessageForSession`). Manual row retries restore the original row and reuse its first transport identity after ambiguous failures; a competing sender cannot dispatch an already-claimed row. A blocked Builder item and every item after it are restored; natural idle auto-send uses the same fail-closed authorization through the non-aborting flush path.
- **Draft send ownership**: `draftAwareAgentChange.ts` resolves agent switches synchronously from the target agent's draft override, then its configured default, then an available fallback, and persists the resolved agent/model/variant atomically into the draft send snapshot. No delayed agent watcher may reapply stale state after rapid switching.
- **Managed branch targets**: fresh and restored managed-developer drafts create an idempotent pending target for the granted branch and keep their effective directory empty until the server returns its exact authorized worktree. `managedBranchTarget.ts` calls the authenticated server operation, and the draft send path waits for that directory before configuration activation or session creation. Branch selectors preserve separate local and remote provenance for the same logical grant, omit ungranted current/root branches, and expose the root worktree only when its real checked-out branch is granted.
- **Mobile control ownership**: `ChatInput.tsx` renders the dedicated compact agent/model buttons, while `ModelControls.tsx` stays mounted with `hideInlineControls` to own only the mobile selector panels. Do not hide that owner with conflicting display utilities or render a second inline control row over the mobile buttons.
- **Primary-agent handoff guard**: `AgentHandoffGuard.tsx` and `agentHandoffCoordinator.ts` inspect the host scheduler before an existing session changes from Orchestrator to Builder. Explicit in-memory clearance distinguishes Builder-first session promotion from restored Builder reconciliation without weakening per-send inspection. Every selector, keyboard cycle, queue, and send path shares the guard; `AgentHandoffDialog.tsx` owns explicit cleanup confirmation, progress locking, safe partial-failure retry, restored-session reconciliation, and truthful inspection-error copy that does not claim task ownership before the scheduler responds.
- **Context window panel**: `ContextUsageWindow.tsx` is a compact left-anchored card above the composer's context trigger. The desktop composer keeps that trigger mounted across draft, loading, unmeasured, and measured states so provider timing cannot make the control appear late; unknown usage is labeled explicitly and never presented as zero. `ComposerContextUsageControl.tsx` receives the selected session's authoritative directory and subscribes to message metadata plus terminal token/compaction parts only, so provider measurement updates remain reactive without streaming-delta repaint fanout. Measured sessions render only the latest provider-reported active-context total and reported token components (uncached input, cached input read/created, output, and reasoning), plus capacity, percentage, and Free Space when the producing message's provider/model limit resolves. Supported OpenAI OAuth rows display their official context window even when the lower internal `limit.input` drives auto-compaction; API-key, unknown, and non-OpenAI rows retain ordinary input-first capacity resolution. It does not estimate or attribute tokens to prompt/tool/message categories. Subagent sessions resolve their own producing models and render as a collapsed tree from `parentSessionId`/`depth`; expanding a data-less row triggers the host's `onExpandSession` exactly once to load its messages and settles to an unmeasured marker when nothing arrives.
- **Provider waiting status**: an accepted xAI turn displays localized `Waiting for Grok` only until it produces its first real output — a tool part, non-empty text, or any reasoning part, empty or ended included, since Grok emits empty already-ended reasoning parts and a delta-materialized provisional text part also counts (`hasAssistantStreamedActivity`). After that the normal status pipeline owns the row for the rest of the message, including the gaps between parts where nothing is live; the copy is non-generic, so firing in a later gap would stomp a live label such as `thinking` or `reading file`. Reasoning, text, tool, retry, abort, and idle return to the existing status pipeline without another store subscription.
- **Deferred chat dialogs**: `lazyChatDialogs.tsx` owns recovery-aware lazy declarations for the issue/PR pickers, checkout stash confirmation, timeline, and Agent handoff dialog. Callers gate each declaration with its authoritative local/store/coordinator open state so closed-at-start overlays do not enter the normal chat startup graph. After first activation, the gate stays mounted and passes `open=false` through, preserving dialog exit/focus lifecycle and local Timeline/Stash state across close and reopen.

## Flow
1. The app composition mounts the agent handoff guard outside the audience-switched `ChatView`, so queued Builder authorization and reconciliation remain live while Bots is visible; the handoff dialog implementation loads only when coordinator state opens it.
2. `ChatContainer` reads current session, messages, status, and permissions/questions from sync + stores.
3. `MessageList` renders timeline and derived plan versions; `ChatInput` prepares/queues/sends user prompts with attachments and queue-time directory/model/agent/plan configuration.
4. Streaming events update sync state; chat auto-follow and status overlays react to live deltas.
5. Low-frequency managed-task projections render one chronological Agent Dispatch card per dispatching assistant message, notifying the existing structural auto-follow path without subscribing chat chrome to the whole scheduler ledger. Parallel launches within one assistant message share its card; later authoritative output reconciles to the original message through exact dispatch identity. Same-child resume, historical recovery-in-place, and manual retry-in-place actions traverse the original task envelope recursively, so provider recovery updates one logical Agent Dispatch row instead of creating a second card. When the latest loaded history contains a compaction boundary, a continuity card is projected immediately above the live status row for only undispositioned lineages that cross that boundary. A narrow root-barrier selector gives live wait turns one authoritative waiting row without exposing polling thoughts.

## Integration
- Primary integrations: `src/sync/*` (`sync-context`, streaming/session actions), `stores/*` (UI/config/queue/git/directory and managed orchestration), `lib/opencode/client`, and `lib/orchestrationApi`.
- Consumed by `components/views/ChatView.tsx` and embedded runtime shells.
- Collaborates with `components/session/*` (pickers), `components/ui/*` primitives, and `hooks/*` for keyboard/voice/activity behavior.
- `HostPrimaryRecovery.tsx`: shared host-owned recovery status, Stop and explicit continuation controls. `PrimaryModelRecovery.tsx` retains manual fallback when host safeguards are unavailable or observation-only. `usePrimaryRecoveryStore` is a bounded low-frequency per-session projection store.
