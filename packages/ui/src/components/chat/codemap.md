# packages/ui/src/components/chat/

## Responsibility
Implements the interactive chat surface: message timeline, composer/input, streaming status UI, permission/question blocking cards, and chat-specific navigation/scroll behavior.

## Design
- **Container + leaf split**: `ChatContainer.tsx` orchestrates state wiring, while specialized children (`MessageList`, `ChatInput`, `StatusRow*`, cards) handle focused rendering.
- **Provider-stall recovery**: `StatusRowContainer.tsx` projects a confirmed semantic tool-input stall as an explicit Stop & Retry action. The action refetches and rechecks the exact pending call before a confirmed abort. An exact initial blank inference shell is instead stopped automatically after the watchdog's final recheck. Both hand off to the existing `PrimaryModelRecovery` card, and neither resends automatically.
- **Performance-oriented memoization**: heavy/hot paths use `React.memo`, stable callbacks, and selector discipline to reduce render fanout during streaming.
- **Local domain helpers**: `lib/`, `hooks/`, and focused helpers such as `chatInputDraftPersistence.ts` encapsulate turn navigation, timeline, blocking requests, composer persistence, and scroll/follow logic. Permanent session deletion synchronously retires a matching active composer target before the normal target-switch save, then releases that local retirement at the switch boundary.
- **Question-card ownership**: `QuestionCard.tsx` owns navigation and request lifecycle, `QuestionOptionRow.tsx` is the sole interactive owner for each option, and `questionCardSubmission.ts` provides session-scoped identities, acknowledgement reconciliation, answer/Skip submission, partial-failure retry filtering, and the duplicate-submit lock. Skip needs no selected answer, rejects every unresolved request represented by the card once, and never resends an acknowledged request.
- **Permission-card shell aliases**: `permissionCardPatterns.ts` owns the complete shell-tool predicate used by permission icons, names, specialized command rendering, and duplicate pattern filtering.
- **Managed-task dispatch projection**: `managedTaskDispatch.ts`, `ManagedTaskList.tsx`, `ManagedTaskRow.tsx`, and `managedTaskListWindow.ts` remove raw `devryan_task` calls from assistant content and render one Agent Dispatch card as the final block in the assistant message that invoked the task. Parallel starts from the same message remain grouped, while later wait/barrier or dispatch messages cannot absorb an earlier card. `managedTaskCompactionProjection.ts` and `ManagedTaskCompactionContinuity.tsx` add one narrow exception: after a real compaction boundary, currently undispositioned task lineages that began before the latest boundary are repeated at the live bottom of the chat until disposition. Genuinely new post-compaction dispatches remain message-local, and retry/resume descendants retain continuity through `priorTaskId` ancestry. Dispatch narration and reasoning retain their relative order above the card, but control-only wait/poll messages suppress internal reasoning so the root shows only the managed waiting status. Preparing starts render provisionally; terminal start failures remain in the same card with a concise sanitized error and no child action. When a restarted web/Electron runtime has not retained the matching scheduler record, the turn projection reconstructs the latest safe task status and child link from persisted managed tool results. Queued rows remain visibly queued without navigation; starting/running rows expose Open Subtask as soon as the canonical child session exists. Same-child resume/recovery lineages collapse to one logical row and link to the canonical child. An active manual retry uses ordinary queued/preparing/running copy; after success the row reports the selected model and thinking level in success styling.
- **Manual model recovery**: `ModelRecoveryCard.tsx`, `PrimaryModelRecovery.tsx`, and `ControlledModelPicker.tsx` provide one Agent Dispatch-style recovery surface with locally controlled model and thinking-level selection for failed primary turns and resumable managed children. A first provider-limit failure closes its safe `agentRetryAvailable` policy flag and shows the embedded card immediately, even if the child still reports provider `retry` while cleanup settles. The failed model and thinking remain preselected, but only an explicit Try Again sends `retry_in_place`; acknowledgement hides the card, and another failed manual attempt restores it on the same child lineage.
- **Contract-aware message rendering**: message parts and tool activity rendering live under `message/parts/*` to map SDK part types to UI blocks. Managed `devryan_browser` calls intentionally suppress command-level presentation and use one generic `Using DevRyan Browser` activity label.
- **Derived plan revision projection**: canonical turn records produce a stable plan trace index. `PlanTurnTraceContext.ts`, `PlanTurnTraceProvider.tsx`, and `usePlanTurnTraceEntry.ts` expose only the current source/version/actionability leaves to plan cards, so superseded plans stay visible but cannot be implemented.
- **Plan persistence and opening**: sync lifecycle detection eagerly ensures the latest completed plan's revision-specific Markdown file even while its chat is unmounted. `PlanCard` consumes the saved pointer, retains missing-metadata fallback and explicit retry, gates implementation on the authoritative path, and sends only that path. Once the current actionable revision is saved, `StatusRow` atomically claims its one-time auto-reveal only on mobile/VS Code and opens the main Plan tab; desktop keeps the context panel closed until the user selects `View Plan`. Plan-mode message rendering treats the actionable Plan card as the terminal visible content block so late provider reasoning cannot displace it.
- **Plan-linked task progress**: saved-plan implementation prompts require one immutable todo per numbered plan task using the `Phase <number>: <task>` contract. `todoSummary.ts` parses only that explicit prefix, and `StatusRow` projects the active phase as `Phase n: Task x/y`, lists only that phase's stripped task titles, and advances from authoritative todo status; ordinary Builder todos retain their whole-list presentation.
- **Queued steering ownership**: `queuedSend.ts` owns atomic FIFO and exact-row claims, stable queue-item identity, per-item dispatch-time transport identity and Builder handoff authorization, captured session directory/model configuration, parent-correlated assistant-completion waits, rollback, and the send-now `steer → flush` boundary. Manual chip retries restore the original row and reuse its first transport identity after ambiguous failures; a competing sender cannot dispatch an already-claimed chip. A blocked Builder item and every item after it are restored; natural idle auto-send uses the same fail-closed authorization through the non-aborting flush path.
- **Draft send ownership**: `draftAwareAgentChange.ts` resolves agent switches synchronously from the target agent's draft override, then its configured default, then an available fallback, and persists the resolved agent/model/variant atomically into the draft send snapshot. No delayed agent watcher may reapply stale state after rapid switching.
- **Mobile control ownership**: `ChatInput.tsx` renders the dedicated compact agent/model buttons, while `ModelControls.tsx` stays mounted with `hideInlineControls` to own only the mobile selector panels. Do not hide that owner with conflicting display utilities or render a second inline control row over the mobile buttons.
- **Primary-agent handoff guard**: `AgentHandoffGuard.tsx` and `agentHandoffCoordinator.ts` inspect the host scheduler before an existing session changes from Orchestrator to Builder. Every selector, keyboard cycle, queue, and send path shares the guard; `AgentHandoffDialog.tsx` owns explicit cleanup confirmation, progress locking, safe partial-failure retry, and restored-session reconciliation.
- **Deferred chat dialogs**: `lazyChatDialogs.tsx` owns recovery-aware lazy declarations for the issue/PR pickers, checkout stash confirmation, timeline, and Agent handoff dialog. Callers gate each declaration with its authoritative local/store/coordinator open state so closed-at-start overlays do not enter the normal chat startup graph. After first activation, the gate stays mounted and passes `open=false` through, preserving dialog exit/focus lifecycle and local Timeline/Stash state across close and reopen.

## Flow
1. `ChatView` mounts the agent handoff guard around `ChatContainer`; the handoff dialog implementation loads only when coordinator state opens it.
2. `ChatContainer` reads current session, messages, status, and permissions/questions from sync + stores.
3. `MessageList` renders timeline and derived plan versions; `ChatInput` prepares/queues/sends user prompts with attachments and queue-time directory/model/agent/plan configuration.
4. Streaming events update sync state; chat auto-follow and status overlays react to live deltas.
5. Low-frequency managed-task projections render at the end of the assistant message containing a fresh-child managed start or retry call and notify the existing structural auto-follow path without subscribing chat chrome to the whole scheduler ledger. Same-child resume, historical recovery-in-place, and manual retry-in-place actions traverse the original task envelope recursively, so provider recovery updates one logical Agent Dispatch row instead of creating a second card. When the latest loaded history contains a compaction boundary, the same card is also projected immediately above the live status row for only undispositioned lineages that cross that boundary. A narrow root-barrier selector gives live wait turns one authoritative waiting row without exposing polling thoughts.

## Integration
- Primary integrations: `src/sync/*` (`sync-context`, streaming/session actions), `stores/*` (UI/config/queue/git/directory and managed orchestration), `lib/opencode/client`, and `lib/orchestrationApi`.
- Consumed by `components/views/ChatView.tsx` and embedded runtime shells.
- Collaborates with `components/session/*` (pickers), `components/ui/*` primitives, and `hooks/*` for keyboard/voice/activity behavior.
