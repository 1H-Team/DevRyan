# packages/ui/src/sync/

## Responsibility
Implements client-side sync primitives for session/event reconciliation and cache updates.

## Design

`session-creation.ts` owns captured creation attempts, the overall deadline,
explicit pre-creation retry policy, persisted unknown outcomes, and bounded
content-free timing marks. `SessionCreationStatus` is the narrow recovery-only
UI consumer for unknown or late-created outcomes;
`session-actions.ts` and `session-ui-store.ts` own transport and safe promotion.
Event-reducer style updates with normalized entities and optimistic-safe merge utilities.
`evidence-store.ts` owns bounded, TTL-evicted per-session checkpoint records and
lazy diff summaries without adding evidence state to high-frequency message
stores.
`session-message-loader.ts` is the provider-owned authority for exact `(directory, session)` history hydration. It coalesces chat/sidebar/model callers, adaptively loads coherent first turns (50→100→150 on web/Electron; 30→50→80→120 in VS Code), owns optimistic reconciliation and freshness, preserves older cursors across 30-message tail refreshes, and rejects late work through generation plus child-store identity checks. Explicit older-history pages remain 200 messages. `message-pagination-store.ts` is now the compatibility mirror consumed by older pagination surfaces; it is not a fetch owner.
`session-load-performance.ts` records opt-in sanitized selection, loader, request, materialization, commit, and first-visible timings through the existing performance collector. Metric labels never include session IDs, directories, or transcript content.
`optimistic.ts` treats an echoed client-generated message ID in a REST page as authoritative confirmation: server-generated part IDs remain untouched, the shadow entry is cleared, and optimistic parts are retained only while the message is still absent.
Draft persistence helpers (`session-draft-storage.ts`) own localStorage keys and migration for new-chat draft state. Authoritative permanent deletion removes both session composer keys and synchronously signals a mounted matching composer so its target-switch effect cannot recreate deleted text or confirmed mentions.
Composer attachments are independently target-scoped by `composer-target.ts`. `input-store.ts` exposes only the active target's attachment leaf, retains a bounded target LRU, and writes normalized payload records through `composer-attachment-storage.ts` to principal-scoped IndexedDB. Draft/session switching restores the exact target; asynchronous file reads retain their initiating target; send, queue, promotion, and permanent deletion clear only their owned target while archive preserves it.
Automatic title ownership is provider-specific and exclusive: the host-side standard title runtime owns accepted non-Cursor prompts in web/Electron and VS Code, the separate server-side Cursor runtime owns Cursor ACP titles, and explicit custom draft titles remain authoritative. Standard placeholders stay neutral and do not subscribe to first-message text; only the narrow Cursor provider-error compatibility path may derive a temporary display title from that text. The sync layer never persists prompt-derived automatic titles. It consumes generated `session.updated` projections immediately and preserves their meaningful title across later placeholder snapshots until a meaningful canonical or manual title arrives.
Plan proposal idle settlement is isolated in `plan-idle-settlement.ts` so completed plan cards can clear stale optimistic busy status without changing generic assistant activity rules. `plan-proposed-detection.ts` returns the exact resolved Markdown, and `sync-context.tsx` owns the primary save trigger through `lib/plans/sessionPlanPersistence.ts`; completed background plans and restored persisted indicators therefore populate their saved pointer without mounting chat UI.
Plan-mode sends inject one shared cross-runtime contract: later same-session prompts revise the latest plan, preserve unchanged context, and return a complete replacement plan rather than an addendum.
Turn and plan-implementation completion detection treats `pending` and `in_progress` todos as authoritative unfinished work. Premature assistant summaries remain visible history but cannot create completion indicators or complete the plan lifecycle; after an automatic continuation, the latest completed assistant message owns the eventual N/N completion.
`client-message-id.ts` owns OpenCode-compatible sortable transport identities used by immediate optimistic sends and assigned to each queued row immediately before that FIFO item dispatches. Queue-item IDs remain stable from enqueue time, while an attempted row's transport ID is preserved across rollback/retry; queued rows also carry their session directory into `sendMessageToSession`.
`selection-store.ts` owns model, agent, plan-mode, per-agent model, and variant choices. It also retains a non-persisted per-session Builder handoff clearance: new Builder-first sessions set it before promotion, successful scheduler inspection sets it before committing Builder, and leaving Builder clears it. Authoritative `session.deleted` handling clears all entries for the permanently deleted session while archive updates preserve reversible choices.
`send-config.ts` shares `lib/agentDefaultResolution.ts` with the config store so
fresh-draft display and transport agree on explicit draft → personal agent
default → live host agent → availability precedence. Existing-session and
queued snapshots remain stronger sources.
`messageQueueStore.ts` persists queued prompt rows by session. Authoritative `session.deleted` handling clears only the deleted session's queue key; archive and failed optimistic deletes preserve queued work.
`contextStore.ts` persists seven maps of session model/agent context, derived usage, and edit modes. Authoritative `session.deleted` handling clears the exact session while preserving unrelated and `__global__` rows, and cancels short-lived deferred usage work so a queued microtask or token poll cannot recreate deleted state.
`permissionStore.ts` persists explicit per-session auto-accept policy and mirrors it to the host notification runtime. Mirror requests are serialized per session; authoritative `session.deleted` removes the exact override and queues `enabled: false` after any older same-session request, while archive preserves policy.
`notification-store.ts` owns bounded completion/error rows, their derived indexes, and compact persisted completion read state. Authoritative `session.deleted` removes the exact session's rows and cancels session UI completion settlement so delayed timers cannot recreate deleted-session indicators; archive preserves reversible completion state.
`session-ui-store.ts` owns exact-session UI routing, abort delivery, plan lifecycle, starter context, and worktree compatibility metadata. Slash-command routing reads both command snapshots and the skill catalog imperatively at send time, keeping catalog churn out of React subscriptions while preserving command transport during snapshot gaps. Its authoritative deletion retirement action lazily removes only the deleted session, aborts its pending controller, rewrites mapped/prefixed plan persistence, and clears the authoritative worktree attachment; archive and unrelated collection references are preserved.
`sync-context.tsx` retires exact `(directory, session)` asynchronous recovery ownership before reducing authoritative `session.deleted`: pending snapshot/lifecycle/blocking-request materializers, child fetches, prefetch revisions, indexed buffered deltas, retry guards, and live-recovery timestamps are invalidated so late responses fail their existing identity/token checks. Archive preserves those recoveries.
`event-pipeline-connection-state.ts` owns connection-state transitions emitted by the event pipeline. Transport switches preserve the current state, and SSE waits for its first parsed or yielded event before publishing `connected`, keeping reconnect-dependent recovery on an authoritative edge.
`sync-refs.ts` owns the imperative `SessionUIState` store reference consumed by `session-actions.ts`; `session-ui-store.ts` registers the completed store after initialization. This preserves the existing action/store cycle without a direct runtime import, lets focused action tests register a narrow store without process-wide module replacement, and lets authoritative `session.deleted` handling synchronously clear an exact stale current-session selection created by deletion in another renderer.
`session-actions.ts` also owns creation-time directory routing: an explicit requested directory is registered and selected before any server-returned textual path alias, while the returned session metadata remains unchanged. Archive and unarchive project membership into both the versioned global index and loaded directory stores before awaiting transport. Optimistic session-removal rollback is reconciliatory: failed archive/delete paths restore only a still-missing target, while failed unarchive restores only the exact optimistic session object it owns, preserving newer live session records in both cases. Failed scoped reverts restore their local snapshot immediately and then always refetch bounded authoritative history so suffix events suppressed during the pending transaction cannot strand concurrent turns. Unexpected-abort refetches keep exact `(directory, session)` promise ownership and recheck it after the response; permanent deletion or directory disposal releases that owner so a late snapshot cannot restore retired messages, while archive preserves recovery.
`session-recency.ts` owns the finite updated/created ordering contract used before session-event branch cloning, inside the directory reducer, during direct title mirroring, and by global upserts. Equal or missing timestamps remain eligible; strictly older records are no-ops except that a meaningful generated/manual title may fill a newer placeholder without replacing any newer metadata.
`session-user-activity.ts` owns the separate low-frequency sidebar ordering
projection: the latest visible root user message, reconciled across optimistic
dispatch/rollback, live events, history materialization, revert, archive, and
deletion. Assistant events never change this projection.
Synthetic session-status compatibility events are normalized in `event-pipeline.ts` before routing/coalescing, terminal assistant status settlement stays provider-neutral and trailing-turn scoped in `event-reducer.ts`, and active-session stale recovery stays scoped to the viewed session in `sync-context.tsx`. An authoritative root `session.idle` or idle `session.status` also triggers one root-scoped managed-orchestration snapshot only while that root still projects active work, repairing a missed terminal managed event across web, Electron, and VS Code without polling. The reducer's message no-op gate includes `parentID`, allowing an owning non-terminal `message.updated` to hydrate a provisional assistant created from an earlier part event. Reconnect status snapshots use per-candidate semantic baselines before both merge points, so a newer live status event cannot be overwritten by a delayed snapshot.
Composer context usage uses a narrow selected-session record projection: message metadata remains reactive, only terminal token/compaction parts can change the projected parts, and streaming text preserves references. The first mounted consumer may bootstrap a missing Anthropic provider snapshot; after that, `sync-context.tsx` refreshes the actively viewed session once at authoritative `session.idle` instead of sampling every intermediate assistant tool-call completion. This keeps provider measurement updates visible without subscribing composer chrome to high-frequency part deltas.
`reconnect-recovery.ts` also owns exact empty pending tool-input, initial blank inference-shell, and long-running Context Mode/shell fingerprints plus their semantic-age policy. `provider-stall-recovery.ts` performs a final resync/fingerprint check before a confirmed abort hands the turn to ordinary provider recovery. Tool-input stalls remain manual; an unchanged blank inference shell is stopped automatically after five minutes, while confirmed long-running tools expose a final-resync Stop action. No recovery prompt or command is ever resent automatically.
`materialization.ts` owns non-regressive HTTP snapshot merging: bounded responses preserve omitted cached messages and live streaming fields, terminal assistant messages cannot be reopened by incomplete same-ID snapshots, and finalized tool parts cannot be restarted by in-flight same-ID snapshots. Linked task-child polling routes through this materializer instead of replacing directory-store message and part branches directly.
Session change ownership is projected outside the hot sync store: `sync-context.tsx` and `use-sync.ts` reconcile completed tool parts into `useSessionChangeAttributionStore.ts` after live events and materialization. Message summaries, `session.diff`, and patch snapshot parts remain shared-working-tree data and never become per-session counters.
Stop-during-retry handling is isolated in `abort-retry-guard.ts`: manual aborts register a per-session guard bounded by the authoritative retry deadline plus settlement grace, suppress stale `retry` statuses across live events, reconnect recovery, and bootstrap snapshots (OpenCode ignores abort during retry backoff), and re-issue bounded aborts when the loop's next attempt fires; guarded idle also completes the stopped assistant's streaming tracker, while new local or authoritative cross-surface user turns and authoritative idle clear the guard.
Transient provider stream recovery is executed through `transient-retry.ts`, which reuses authoritative sync snapshots and the existing per-session send pipeline for both automatic and manual retries.
Directory lifecycle ownership is centralized in `child-store.ts`; `directory-disposal.ts` provides cold-path routing/timer cleanup and restart-safe provider teardown. `sync-context.tsx` fans that boundary out to prefetch, pending-delta, session-child, materializer, action/ref, reconnect, toast, and event-pipeline resources, while generation/store-identity guards prevent late async completions from repopulating an evicted directory.
`ChildStoreManager.subscribeSessionLists` is the low-frequency cross-directory membership channel used by the Electron browser-claim owner; it ignores message, part, status, and other hot state changes.
`session-selectors.ts` owns exact-session/directory leaf projections and referentially stable direct-child arrays used by `useSession`, `useSessionDirectory`, and `useSessionChildren`; mounted chat leaves do not scan broad session collections.
Read subscriptions distinguish passive cache access from runtime bootstrap: explicit inactive-directory hooks create non-bootstrapping stores, while provider setup selects only the normalized active directory. Reconnect, foreground, transport, and replay recovery additionally revisit already-initialized background stores only while they still project `busy` or `retry`; idle passive stores remain untouched. Imperative selection and materialization keep explicit bootstrap authority.

## Flow
SSE/polling events enter reducers, then produce store patches consumed by chat/session UI. Selected-session hydration is an exact-key loader path and remains separate from broad reconnect snapshot recovery.

## Integration
Bridges lib/opencode streams with Zustand stores and session/chat components.
- Primary host recovery: `event-pipeline.ts` consumes versioned per-session projections before ordinary event reduction. `provider-stall-recovery.ts` yields to an enforcing host; reconnect refreshes the narrow recovery projection. The host remains the admission and cancellation authority.
