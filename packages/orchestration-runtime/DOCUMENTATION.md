# Managed Orchestration Runtime

## Purpose

This package is the single policy owner for DevRyan-managed sub-agent work. It is deliberately separate from OpenCode/provider-native task events, which remain observational and are never admitted, counted, or cancelled by this runtime.

## Contract boundary

Managed tasks use `owner: "devryan"` and `dvr_task_` identities. A record carries stable root/parent/child identity, an optional private `dispatchGroupId` derived from the parent assistant message, directory, deterministic sequence, builder/orchestrator ownership mode, a queue-time provider/model/agent/variant snapshot, attempt lineage, lifecycle timestamps, and explicit partial/failure metadata. Council and legacy records remain ungrouped. Retry, resume, and manual retry-in-place follow-ups inherit the source group. Historical `recover_in_place` records remain valid so ledgers created by older releases hydrate and reconcile without migration.

Queued work must survive application restart, so the private durable record includes its text prompt. Labels are limited to 512 UTF-8 bytes and prompts to 256 KiB. Broadcast task events omit prompt, idempotency key, dispatch group, and lease token; their safe task record exposes `agentRetryAvailable` as a live policy projection plus a derived `failureKind` for explicit provider-usage-limit presentation. The flag can therefore change from `true` while an initial grouped Orchestrator attempt runs to `false` when that attempt settles on a provider usage, session, quota, or rate limit. Compaction emits an identity-only `openchamber:managed-task-removed` event. Recoverable previews are limited separately to 64 KiB; complete output stays in the canonical OpenCode child session.

## Scheduler policy

`createManagedTaskScheduler()` serializes every ledger mutation and immediately admits every eligible queued task without imposing an artificial concurrency cap. Queue sequence remains monotonic across the runtime and recovered queued work launches in deterministic order. Idempotency is scoped by root session and key.

The scheduler owns explicit transitions, per-root builder/orchestrator mode exclusion, child-session and provider-acceptance checkpoints, isolated task/descendant cancellation, bounded provider-abort waits, execution deadlines, and the 60-second starting-lease reconciliation check. Reconciliation distinguishes transient owner unavailability from an authoritative missing child: transient checks schedule a lease-scoped retry against the same child without mutating task state or creating a result envelope, while the existing task deadline remains the upper bound. Both execution checkpoints return authoritative lease ownership: a late launch receives `false` after terminal settlement, lease replacement, or shutdown instead of mistaking an ignored durable write for success. Provider-native workers have no admission path into this package.

`waitForTask(taskId, { signal, timeoutMs? })` remains an unbounded terminal wait when `timeoutMs` is omitted. A positive finite timeout creates only a polling slice: expiry returns a cloned latest task snapshot, including a still-live `queued`, `starting`, or `running` status, without cancelling or mutating the task and without changing its execution deadline. Slice timers use the scheduler's injected clock and are released on expiry, terminal settlement, caller abort, or shutdown. Dispatch-barrier waits remain unbounded and do not opt into slices.

`waitForResultAction(taskId, { signal })` is the abortable synchronization point for explicit result disposition. It returns a cloned envelope immediately when an action already exists; otherwise it remains pending until the durable acknowledgement commits. Provider-limit recovery uses this wait as the fast path so the parent tool invocation stays alive while the user selects a replacement model, without polling, auto-acknowledging, or weakening the dispatch barrier. Caller abort and scheduler shutdown remove and reject the waiter.

`listReadyProviderRecoveryContinuations({ sessionId? })` derives restart-safe parent handoffs directly from durable retry-in-place lineage. It returns only terminal, non-provider-limited follow-ups for grouped Orchestrator work whose provider-limited source was acknowledged with `retry_in_place` and whose own result is still unacknowledged. Ungrouped work, active work, repeated provider-limit failures, already dispositioned results, and unrelated session hints are excluded. The packaged plugin checks this list only when the root is authoritatively idle, so an attached live waiter remains the preferred path; after an external tool-call timeout detaches that waiter, the same ledger state can wake the parent exactly once without copying child output.

Grouped Orchestrator work permits one agent-directed `retry` or `resume`: the initial task is attempt 1 and its recovery is attempt 2. A further grouped agent recovery fails before envelope acknowledgement with `managed_retry_limit_reached`. Provider-limit results are a stricter exception: while their envelope is unacknowledged, agent-driven `continue`, `retry`, `resume`, `recover_in_place`, and `abandon` all fail with `manual_model_recovery_required`. Only UI-originated `retry_in_place` may acknowledge them, and it must provide an explicit provider, model, and variant selection (`null` means Default). The retry-in-place executor reuses the canonical child so no second child session is created. New `recover_in_place` attempts are rejected, but its durable enum remains accepted for upgrade-safe hydration and reconciliation. Web/Electron and VS Code expose both deterministic conflicts as HTTP 409. Council and legacy ungrouped tasks retain their existing non-provider-limit action behavior.

`waitForDispatchBarrier(rootSessionId, { signal })` is the scheduler-owned primary-agent gate. It ignores ungrouped work, waits while any grouped task under the root is queued/starting/running, then returns `awaiting_acknowledgement` with terminal task IDs whose result envelope still has `action: null`. It returns `clear` only when every group is fully dispositioned. Retries, resumes, and in-place recoveries keep the original group locked through their follow-up result. Aborted barrier waits reuse task waiters and remove them immediately on signal cancellation.

`inspectDispatchBarrier(rootSessionId)` reports `active`, `awaiting_acknowledgement`, or `clear` without waiting or mutating. `inspectAgentHandoff(...)` uses that same grouped Orchestrator scope to prepare an Orchestrator-to-Builder switch without touching Council or legacy ungrouped work. Confirmed handoff temporarily locks the root against new grouped submissions and admissions, cancels nonterminal tasks in scheduler order, abandons terminal-unreviewed envelopes, continues after per-task failures, verifies the barrier again, and releases the lock in every outcome. Repeated confirmations with the same key coalesce while in flight and safely retry after a partial result; a conflicting key fails explicitly.

Durable mutations and event publication use separate serialized lanes. A slow or reentrant event sink therefore cannot hold the ledger mutation lock, while event invocation order still follows committed task order. Shutdown attempts executor cleanup even when the final durable save fails, and shutdown before initialization never overwrites an existing owner ledger.

Terminal tasks are immutable. Each gets one result envelope retaining status, partial flag, failure reason, bounded preview, canonical child message/tool references, and attempt lineage. Successful completion requires a useful final assistant response after the child leaves live `busy`/`retry` state and every observed tool part is final. Provider `busy` and transient `retry` snapshots remain live and authoritative; observation continues against the same child without aborting or replaying its prompt. A definite usage, session, quota, or rate-limit retry instead settles immediately as a resumable `provider_usage_limit` failure, preserves partial work and canonical references, starts the existing bounded retry-loop cleanup, and projects `agentRetryAvailable: false` so Model Recovery is actionable immediately. The cleanup status cannot hide or auto-acknowledge that user decision. Temporary observation timeouts, abort-shaped request failures, network errors, and retryable HTTP responses wait one polling interval before retrying, while the last successful preview and canonical references remain available. When OpenCode instead records the exact transient provider failure `The operation timed out` as a terminal assistant message, the executor sends one idempotent fixed continuation into the same canonical child with the queue-time execution snapshot; it never replays the original prompt. Restart reconciliation keeps that first timeout live so the observer can perform the same recovery. A second terminal timeout settles honestly with retained partial work rather than looping. When a provider becomes idle after completed tool activity but its terminal assistant message has no final text, the executor likewise sends one transcript-recorded fixed continuation into the same child using the queue-time execution snapshot. Restart reconciliation keeps only the first empty ending live; a second empty ending or a transcript that already contains that continuation settles as a visible resumable failure, preventing duplicate prompts and recovery loops. A non-retryable observation failure settles as resumable `interrupted` work with that retained partial output. An assistant `finish: "tool-calls"` record is an intermediate handoff even when it has a completed timestamp, and stable idle state alone never promotes tool activity to success. A bare completed assistant-message shell is recorded as a resumable failure with `partial=false` only after the bounded same-child continuation also fails and the child is no longer live with no in-flight tools. A fresh start that loses ownership before prompting, or after a late prompt acknowledgement, aborts and deletes its newly created child and never enters observation. In-place recovery ownership loss aborts without deleting the pre-existing canonical child. Cleanup attempts abort and deletion independently; confirmed deletion is authoritative even when a pre-prompt provider abort has no state to stop. Continue/abandon acknowledge ordinary results without work; retry creates a new child; resume only observes the existing child; `retry_in_place` waits for explicit retry cleanup and sends a fixed continuation into the same child with the selected provider/model/variant snapshot. Historical `recover_in_place` executions retain the same reconciliation semantics. Manual cancellation and retry-in-place recovery retain their existing bounded abort guards.

Runtime owners give every ordinary model-directed attempt at least a 30-minute deadline and enforce a 60-minute floor for Oracle reviews, including retry, resume, and retry-in-place follow-ups. Packaged Orchestrator guidance sizes other explicit deadlines by delegated scope: 30 minutes for discovery and small fixes, at least 60 minutes for multi-file implementation plus tests, and at least two hours when the child also owns builds or browser verification. Non-Oracle follow-ups receive a fresh 30-minute deadline when the caller does not supply one; the scheduler's hard deadline remains the upper bound for observation. Historical recovery-in-place attempts retain the same agent-aware default during reconciliation. Council submits use a private deadline class that preserves the separate three-minute councillor limit.

When a hard deadline expires, the deadline remains the task's primary failure reason even if provider abort cleanup is slow or unconfirmed. The scheduler aborts the transport request at its own bounded cleanup deadline and logs cleanup failure separately. If immediate recovery also fails but the timed-out task has a canonical child session, the result remains resumable so the parent can use its one managed `resume` attempt to observe that same child after its active tool settles; the original prompt is never replayed. Manual cancellation and agent-handoff cleanup do not gain this timeout-specific resumability fallback.

`formatManagedTaskDisplayName(label)` is the shared presentation boundary for durable task labels. It trims and normalizes whitespace, hyphens, and underscores; collapses adjacent duplicate words; title-cases ordinary lowercase words; keeps internal short articles and conjunctions lowercase; canonicalizes known technical initialisms (API, CLI, CSS, HTML, HTTP, JSON, MCP, PDF, PR, SDK, SSE, UI, URL, and UX); and preserves intentional mixed or all-uppercase token casing. The raw label remains immutable in the ledger and safe event projection, while both canonical child-session creation and Agent Dispatch rows use the same display name.

On restart, queued tasks retain order. Starting/running children are reconciled: live children resume observation, terminal children settle without another prompt, transient runtime/transport unavailability retries reconciliation without replaying the prompt, and only an authoritatively missing child becomes interrupted while preserving recoverable output. Shutdown clears owned timers/waiters, including reconciliation retries, while leaving nonterminal records durable for the next owner.

## Persistence bounds

Owner adapters provide atomic `load()` and `save()` operations. Legacy records missing `dispatchGroupId` hydrate to `null` before validation so upgrades do not quarantine historical ledgers or lock old results. Before every save, the core removes the oldest unreferenced terminal history to enforce 2,000 terminal records, 90 days, and 20 MiB of UTF-8 serialized state. Each successfully persisted removal is published before the task event whose commit caused it, and a task removed by its own terminal commit is not republished. This lets long-lived renderers release the same projection without polling or retaining tombstones. Nonterminal work, unacknowledged grouped results, and retained attempt lineage are never compacted; new work is rejected honestly when protected state alone cannot fit the byte boundary.

## Public entrypoints

- `createManagedTaskRecord(input)`: creates and validates a queued task record.
- `formatManagedTaskDisplayName(label)`: derives the shared child-session and Agent Dispatch display name without mutating the durable label.
- `validateManagedTaskRecord(task)`: rejects malformed, provider-owned, non-JSON, or over-limit records.
- `isTerminalManagedTaskStatus(status)`: classifies immutable terminal states.
- `toManagedTaskEvent(task)`: creates the safe `openchamber:managed-task` projection, including `agentRetryAvailable` without exposing the private dispatch group.
- `toManagedTaskRemovalEvent(task)`: creates the safe identity-only `openchamber:managed-task-removed` projection.
- `createManagedTaskScheduler(options)`: creates the runtime scheduler owner.
- `scheduler.waitForTask(taskId, options)`: waits until terminal by default, or returns the latest cloned snapshot after an optional positive finite polling slice.
- `scheduler.waitForResultAction(taskId, options)`: waits for a durable result action and returns a cloned acknowledged envelope.
- `scheduler.listReadyProviderRecoveryContinuations(options)`: derives terminal retry-in-place results that need an idle parent continuation after a detached wait.
- `scheduler.waitForDispatchBarrier(rootSessionId, options)`: waits for grouped work to settle and reports any result envelopes still awaiting disposition.
- `scheduler.inspectDispatchBarrier(rootSessionId)`: reports grouped barrier state without blocking.
- `scheduler.inspectAgentHandoff(scope)` / `scheduler.confirmAgentHandoff(scope)`: inspect or confirm the explicit grouped Orchestrator-to-Builder cleanup handoff.
- `createManagedOpenCodeExecutor(options)`: executes and reconciles canonical child sessions through an injected web/VS Code transport without owning HTTP or provider state.
- `resolveProviderPromptTools(providerId, agent?)`: returns the shared, minimal provider/agent prompt-tool override. Copilot disables both OpenCode names for the optional Resend MCP namespace. Orchestrator keeps its root prompt on the managed harness surface by disabling provider-native `task`, the invalid placeholder tool, and ambient MCP tools; both policies merge when applicable.
- `createManagedTaskResultEnvelope(task, options)`: creates a terminal parent handoff.
- `compactManagedOrchestrationState(state, options)`: applies durable count/age/byte policy.
- `assertManagedTaskTransition(previous, next)`: validates lifecycle and immutable identity.
