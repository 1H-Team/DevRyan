# Managed Orchestration Runtime

## Purpose

This package is the single policy owner for DevRyan-managed sub-agent work. It is deliberately separate from OpenCode/provider-native task events, which remain observational and are never admitted, counted, or cancelled by this runtime.

## Contract boundary

Managed tasks use `owner: "devryan"` and `dvr_task_` identities. A record carries stable root/parent/child identity, an optional private `dispatchGroupId` derived from the parent assistant message, the originating managed-tool `dispatchCallId`, directory, deterministic sequence, builder/orchestrator ownership mode, an immutable private `readOnly` policy, a queue-time provider/model/agent/variant snapshot, attempt lineage, lifecycle timestamps, and explicit partial/failure metadata. Council and legacy records remain ungrouped. Retry, resume, and manual retry-in-place follow-ups inherit the source group, dispatch-call identity, and read-only policy, so recovery stays linked to the original dispatch and cannot acquire write access. Historical records without a dispatch call and `recover_in_place` records hydrate without migration.

`classifyProviderTransportFailure(name, detail)` is the shared normalized transport boundary used by managed execution and the primary chat runtime. It returns `request_timeout`, `response_header_timeout`, `stream_idle_timeout`, `connection_failure`, or `null`, with auth, model-selection, certificate, abort, and unrelated provider errors taking precedence over transport wording. Managed children receive one bounded same-child continuation for any of those normalized transport failures; primary-session recovery remains explicit and manual.

`isManagedTransientTransportContinuationPrompt(value)` recognizes only the two fixed timeout/connection continuation prompts written by this executor, `isManagedResumeContinuationPrompt(value)` recognizes the fixed active-resume prompt, and `isManagedRetryInPlacePrompt(value)` recognizes the manual same-child recovery prompt, each with or without the exact plan-mode read-only prefix. Shared UI uses those deterministic transcript markers together with the authoritative child-task projection to fold a recovered managed turn for display; arbitrary user text and primary-session failures cannot enter that path.

Queued work must survive application restart, so the private durable record includes its text prompt and read-only policy. Labels are limited to 512 UTF-8 bytes and prompts to 256 KiB. Broadcast task events omit prompt, idempotency key, the raw dispatch group, read-only policy, and lease token; they retain the non-secret `dispatchCallId`, expose only a `dispatchGrouped` boolean for recovery-policy parity, and expose `agentRetryAvailable` plus derived `failureKind`. The flag can therefore change from `true` while an initial grouped Orchestrator attempt runs to `false` when that attempt settles on a provider usage, session, quota, or rate limit. Verified invalid-prompt policy rejections project `failureKind: provider_prompt_rejected`, while scheduler-owned hard deadlines project `failureKind: deadline_exceeded` from their stable reason prefix. Compaction emits an identity-only `openchamber:managed-task-removed` event. Recoverable previews are limited separately to 64 KiB; complete output stays in the canonical OpenCode child session.

## Scheduler policy

`createManagedTaskScheduler()` serializes every ledger mutation and immediately admits every eligible queued task without imposing an artificial concurrency cap. Queue sequence remains monotonic across the runtime and recovered queued work launches in deterministic order. Idempotency is scoped by root session and key.

Designer is implementation-only. The scheduler rejects every new `readOnly + designer` start or recovery with `MANAGED_READ_ONLY_AGENT_UNSUPPORTED`; read-only Explorer and other planning specialists remain eligible. The guard runs after idempotent replay lookup but before persistence or publication, so historical ledger records remain loadable while no new plan-mode Designer execution can begin.

The scheduler owns explicit transitions, per-root builder/orchestrator mode exclusion, child-session and provider-acceptance checkpoints, isolated task/descendant cancellation, bounded provider-abort waits, execution deadlines, and the 60-second starting-lease reconciliation check. Reconciliation distinguishes transient owner unavailability from an authoritative missing child: transient checks schedule a lease-scoped retry against the same child without mutating task state or creating a result envelope, while the existing task deadline remains the upper bound. Both execution checkpoints return authoritative lease ownership: a late launch receives `false` after terminal settlement, lease replacement, or shutdown instead of mistaking an ignored durable write for success. Provider-native workers have no admission path into this package.

`waitForTask(taskId, { signal, timeoutMs? })` remains an unbounded terminal wait when `timeoutMs` is omitted. A positive finite timeout creates only a polling slice: expiry returns a cloned latest task snapshot, including a still-live `queued`, `starting`, or `running` status, without cancelling or mutating the task and without changing its execution deadline. Slice timers use the scheduler's injected clock and are released on expiry, terminal settlement, caller abort, or shutdown. Dispatch-barrier waits remain unbounded and do not opt into slices.

`waitForResultAction(taskId, { signal })` is the abortable synchronization point for explicit result disposition. It returns a cloned envelope immediately when an action already exists; otherwise it remains pending until the durable acknowledgement commits. The compatibility RPC may still use it to observe a UI acknowledgement, but ordinary model-facing waits return a structured `manualRecoveryRequired` terminal result immediately instead of depending on a tool invocation surviving while the user selects a replacement model. The envelope remains unacknowledged and the dispatch barrier stays locked. Caller abort and scheduler shutdown remove and reject the waiter.

`listReadyProviderRecoveryContinuations({ sessionId? })` retains its compatibility name while deriving restart-safe parent handoffs for terminal grouped Orchestrator work whose envelope is still unacknowledged. Entries use `kind: collect`. Results parked for a user-selected model are omitted: the attached wait already returns `manualRecoveryRequired`, the envelope stays unacknowledged, and the Model Recovery card is the user-action surface. The packaged plugin checks this list only when the root is authoritatively idle and wakes collectable work for normal disposition. Ungrouped work, active work, parked Model Recovery results, already dispositioned results, and unrelated session hints remain excluded.

Grouped Orchestrator work permits one agent-directed `retry` or `resume`: the initial task is attempt 1 and its recovery is attempt 2. If that resumable recovery also fails or is interrupted, `agentRetryAvailable` becomes false and agent-driven `continue`, `retry`, `resume`, `recover_in_place`, and `abandon` all fail before envelope acknowledgement with `manual_model_recovery_required`; the same strict gate applies immediately to provider-limit failures. Provider prompt rejection is the narrow exception: same-child `resume`, `recover_in_place`, and `retry_in_place` are forbidden, and `retry` requires a non-empty prompt override that differs from the rejected prompt, so the sole agent recovery creates a fresh child while preserving the queue-time execution snapshot. If attempt 2 is also prompt-rejected, it remains dispositionable with `continue` or `abandon` and never enters Model Recovery; the grouped retry ceiling still prevents attempt 3. Only UI-originated `retry_in_place` may acknowledge ordinary exhausted or provider-limit recovery results, and it must provide an explicit provider, model, and variant selection (`null` means Default). The separately confirmed Orchestrator-to-Builder handoff may abandon those parked results through a private scheduler-only capability because that confirmation explicitly chooses cleanup instead of recovery; ordinary acknowledgement callers cannot set the capability. The retry-in-place executor reuses the canonical child so no second child session is created. Non-resumable grouped attempts retain the deterministic `managed_retry_limit_reached` ceiling for extra retry/resume requests. New `recover_in_place` attempts are rejected, but its durable enum remains accepted for upgrade-safe hydration and reconciliation. Web/Electron and VS Code expose these policy conflicts as HTTP 409. Council and legacy ungrouped tasks retain their existing non-provider-limit action behavior.

`waitForDispatchBarrier(rootSessionId, { signal })` is the scheduler-owned primary-agent gate. It ignores ungrouped work, waits while any grouped task under the root is queued/starting/running, then returns `awaiting_acknowledgement` with terminal task IDs whose result envelope still has `action: null`. It returns `clear` only when every group is fully dispositioned. Retries, resumes, and in-place recoveries keep the original group locked through their follow-up result. Aborted barrier waits reuse task waiters and remove them immediately on signal cancellation.

`inspectDispatchBarrier(rootSessionId)` reports `active`, `awaiting_acknowledgement`, or `clear` without waiting or mutating. `inspectAgentHandoff(...)` uses that same grouped Orchestrator scope to prepare an Orchestrator-to-Builder switch without touching Council or legacy ungrouped work. Confirmed handoff temporarily locks the root against new grouped submissions and admissions, cancels nonterminal tasks in scheduler order, abandons terminal-unreviewed envelopes (including parked manual-recovery results), continues after per-task failures, verifies the barrier again, and releases the lock in every outcome. Repeated confirmations with the same key coalesce while in flight and safely retry after a partial result; a conflicting key fails explicitly.

Durable compaction may remove an old task after its result was acknowledged. The packaged model-facing plugin treats a later reference to that removed identity as stale only when a fresh runtime snapshot is available, bridge ownership is healthy, no recovery warning exists, and `inspectDispatchBarrier(rootSessionId)` is authoritatively `clear`. It then returns `stale_task_reference` as a no-op instead of reconstructing or replaying the child. Retained envelopes with an existing action return `already_dispositioned`. Any snapshot warning, ownership failure, malformed response, or current active/acknowledgement barrier remains fail-closed and preserves the current authoritative task IDs.

Durable mutations and event publication use separate serialized lanes. A slow or reentrant event sink therefore cannot hold the ledger mutation lock, while event invocation order still follows committed task order. Shutdown attempts executor cleanup even when the final durable save fails, and shutdown before initialization never overwrites an existing owner ledger.

Terminal tasks are immutable. Each gets one result envelope retaining status, partial flag, failure reason, bounded preview, canonical child message/tool references, and attempt lineage. Successful completion requires a useful final assistant response after the child leaves live `busy`/`retry` state and every observed tool part is final. Provider `busy` and transient `retry` snapshots remain live and authoritative; observation continues against the same child without aborting or replaying its prompt. A definite usage, session, quota, or rate-limit retry instead settles immediately as a resumable `provider_usage_limit` failure, preserves partial work and canonical references, starts the existing bounded retry-loop cleanup, and projects `agentRetryAvailable: false` so Model Recovery is actionable immediately. The cleanup status cannot hide or auto-acknowledge that user decision. Temporary observation timeouts, abort-shaped request failures, network errors, and retryable HTTP responses wait one polling interval before retrying, while the last successful preview and canonical references remain available. When OpenCode instead records a normalized request, response-header, stream-idle, or connection failure as a terminal assistant message, the executor sends one idempotent fixed transport continuation into the same canonical child with the queue-time execution snapshot; it never replays the original prompt. Restart reconciliation keeps that first transport failure live so the observer can perform the same recovery, and legacy timeout-continuation prompts remain recognized to prevent duplicate recovery after upgrades. A second terminal transport failure settles honestly with retained partial work rather than looping. When a provider becomes idle after completed tool activity but its terminal assistant message has no final text, the executor likewise sends one transcript-recorded fixed continuation into the same child using the queue-time execution snapshot. Restart reconciliation keeps only the first empty ending live; a second empty ending or a transcript that already contains that continuation settles as a visible resumable failure, preventing duplicate prompts and recovery loops. A non-retryable observation failure settles as resumable `interrupted` work with that retained partial output. An assistant `finish: "tool-calls"` record is an intermediate handoff even when it has a completed timestamp, and stable idle state alone never promotes tool activity to success. A bare completed assistant-message shell is recorded as a resumable failure with `partial=false` only after the bounded same-child continuation also fails and the child is no longer live with no in-flight tools. A fresh start that loses ownership before prompting, or after a late prompt acknowledgement, aborts and deletes its newly created child and never enters observation. In-place recovery ownership loss aborts without deleting the pre-existing canonical child. Cleanup attempts abort and deletion independently; confirmed deletion is authoritative even when a pre-prompt provider abort has no state to stop. Continue/abandon acknowledge ordinary results without work, but cannot consume a resumable result whose user recovery gate is active; retry creates a new child; resume marks live observation accepted when the canonical child is still active, otherwise sends one transcript-marked same-child continuation with the queue-time execution snapshot. A restart relaunches an unaccepted resume only when that marker is absent and observes it without duplication when the marker is present. `retry_in_place` waits for explicit retry cleanup and sends a fixed continuation into the same child with the selected provider/model/variant snapshot. Every OpenCode-backed managed child prompt disables provider-native `task`, including initial execution and every same-child continuation, so additional delegation stays root-owned regardless of project agent permissions or `readOnly` state. Read-only tasks additionally prepend an explicit inspection-only instruction and disable every shell, workspace mutation, skill, and MCP surface. Cursor SDK managed tasks fail before child creation when read-only is required because that SDK does not expose enforceable per-prompt write restrictions. Historical `recover_in_place` executions retain the same reconciliation semantics. Manual cancellation and retry-in-place recovery retain their existing bounded abort guards.

`supportsManagedReadOnlyProvider(providerId)` and `supportsManagedReadOnlyAgent(agent)` are the shared compatibility boundaries. Web/Electron and VS Code reject an incompatible read-only provider with `MANAGED_READ_ONLY_PROVIDER_UNSUPPORTED` and reject Designer with `MANAGED_READ_ONLY_AGENT_UNSUPPORTED` before scheduler persistence. The scheduler repeats the agent gate for recovery overrides, and the executor retains fail-closed checks before child creation or same-child prompting. The provisioned managed-tool plugin resolves plan policy before execution selection, rejects Designer immediately, and otherwise substitutes the active non-Cursor parent model, then the configured non-Cursor Plan-agent model; if no compatible provider exists, it returns the provider error without creating a managed task.

A managed child that remains `busy` with no transcript progress for five minutes is treated as a silent provider-stream stall unless its current attempt has a tool that is actually running or still carries material input. An exact `pending` tool shell with no start time, structured input, or raw input means the provider stopped while constructing the call; it does not exempt the child from recovery and is aborted before any continuation is sent. In-flight tool checks are scoped after the latest recognized same-child continuation, so an abandoned pending tool from an earlier attempt cannot keep a recovered attempt live forever. The executor aborts only that child and sends the existing timeout continuation once in the same canonical session, preserving completed tools and partial work without replaying the original prompt. Provider `retry` backoff and real running tools remain exempt. If the continuation also becomes silent, the child is stopped and settles as a visible resumable failure with a stream-idle-timeout reason instead of remaining busy until its task deadline.

Resume waits up to 30 seconds for a just-aborted `busy` turn to finish teardown, then anchors its continuation to the pre-prompt assistant tail. Resume and `retry_in_place` ignore that stale tail until a new assistant message appears, re-post a continuation at most once after a two-minute start grace, and then settle honestly instead of waiting to the hard deadline. Transcript observation restores authoritative `info.time.created` order when complete timestamps expose mixed legacy Cursor and native OpenCode ID ordering, so a newer recovery tail cannot be mistaken for stale work or trigger duplicate prompts. The anchor is per dispatch rather than transcript-lifetime, so a child may be recovered again after an earlier continuation. Aborted-tool boilerplate is excluded from preview selection so the latest substantive assistant text remains visible while canonical references are retained.

Runtime owners give Fixer and Oracle attempts at least a 60-minute deadline, including retry, resume, and retry-in-place follow-ups; other ordinary specialists retain a 30-minute floor. The Fixer floor is a recovery boundary for one closed work unit, not permission to widen a task or replace decomposition. Packaged Orchestrator guidance reserves larger explicit deadlines for closed, inherently indivisible build, browser, or release-verification work. Every follow-up inherits at least the source task's full `timeoutAt - createdAt` window, transitively across attempts; an explicit larger recovery timeout wins, while a source without a deadline keeps the owner-supplied floor. The scheduler's hard deadline remains the upper bound for observation. Historical recovery-in-place attempts retain the same agent-aware default during reconciliation. Council submits use a private deadline class that preserves the separate three-minute councillor limit.

When a hard deadline expires, the deadline remains the task's primary failure reason even if provider abort cleanup is slow or unconfirmed. The scheduler aborts the transport request at its own bounded cleanup deadline and logs cleanup failure separately. If the timed-out task has a canonical child session, the result remains resumable so the parent can use its one managed `resume` attempt: a still-live child remains under observation, while an idle terminal child receives one same-child continuation from its saved progress. The original prompt is never replayed. Manual cancellation and agent-handoff cleanup do not gain this timeout-specific resumability fallback.

`formatManagedTaskDisplayName(label)` is the shared presentation boundary for durable task labels. It trims and normalizes whitespace, hyphens, and underscores; collapses adjacent duplicate words; title-cases ordinary lowercase words; keeps internal short articles and conjunctions lowercase; canonicalizes known technical initialisms (API, CLI, CSS, HTML, HTTP, JSON, MCP, PDF, PR, SDK, SSE, UI, URL, and UX); and preserves intentional mixed or all-uppercase token casing. The raw label remains immutable in the ledger and safe event projection, while both canonical child-session creation and Agent Dispatch rows use the same display name.

On restart, queued tasks retain order. Starting/running children are reconciled: live children resume observation, an unaccepted `resume` relaunches only when its transcript continuation marker is absent, terminal children otherwise settle without another prompt, transient runtime/transport unavailability retries reconciliation without replaying the prompt, and only an authoritatively missing child becomes interrupted while preserving recoverable output. Shutdown clears owned timers/waiters, including reconciliation retries, while leaving nonterminal records durable for the next owner.

## Persistence bounds

Owner adapters provide atomic `load()` and `save()` operations. Legacy records missing `dispatchGroupId` hydrate to `null`, and records predating plan-mode task policy hydrate with `readOnly: false`, before validation so upgrades do not quarantine historical ledgers or lock old results. Before every save, the core removes the oldest unreferenced terminal history to enforce 2,000 terminal records, 90 days, and 20 MiB of UTF-8 serialized state. Each successfully persisted removal is published before the task event whose commit caused it, and a task removed by its own terminal commit is not republished. This lets long-lived renderers release the same projection without polling or retaining tombstones. Nonterminal work, unacknowledged grouped results, and retained attempt lineage are never compacted; new work is rejected honestly when protected state alone cannot fit the byte boundary.

## Public entrypoints

- `createManagedTaskRecord(input)`: creates and validates a queued task record.
- `formatManagedTaskDisplayName(label)`: derives the shared child-session and Agent Dispatch display name without mutating the durable label.
- `supportsManagedReadOnlyAgent(agent)`: returns false for Designer and missing identities so plan-mode work cannot enter implementation ownership.
- `MANAGED_READ_ONLY_AGENT_UNSUPPORTED` / `MANAGED_READ_ONLY_AGENT_UNSUPPORTED_MESSAGE`: stable cross-runtime pre-admission failure contract for plan-mode Designer dispatch.
- `validateManagedTaskRecord(task)`: rejects malformed, provider-owned, non-JSON, or over-limit records.
- `isTerminalManagedTaskStatus(status)`: classifies immutable terminal states.
- `toManagedTaskEvent(task)`: creates the safe `openchamber:managed-task` projection, including `agentRetryAvailable` without exposing the private dispatch group.
- `toManagedTaskRemovalEvent(task)`: creates the safe identity-only `openchamber:managed-task-removed` projection.
- `createManagedTaskScheduler(options)`: creates the runtime scheduler owner.
- `scheduler.waitForTask(taskId, options)`: waits until terminal by default, or returns the latest cloned snapshot after an optional positive finite polling slice.
- `scheduler.waitForResultAction(taskId, options)`: waits for a durable result action and returns a cloned acknowledged envelope.
- `scheduler.listReadyProviderRecoveryContinuations(options)`: derives collectable terminal results that need an idle parent continuation after a detached wait. Parked Model Recovery results are omitted.
- `scheduler.waitForDispatchBarrier(rootSessionId, options)`: waits for grouped work to settle and reports any result envelopes still awaiting disposition.
- `scheduler.inspectDispatchBarrier(rootSessionId)`: reports grouped barrier state without blocking.
- `scheduler.inspectAgentHandoff(scope)` / `scheduler.confirmAgentHandoff(scope)`: inspect or confirm the explicit grouped Orchestrator-to-Builder cleanup handoff.
- `createManagedOpenCodeExecutor(options)`: executes and reconciles canonical child sessions through an injected web/VS Code transport without owning HTTP or provider state.
- `isManagedTransientTransportContinuationPrompt(value)`: recognizes the executor's exact timeout/connection continuation transcript records, including their read-only form.
- `isManagedResumeContinuationPrompt(value)`: recognizes the executor's exact active-resume continuation transcript record, including its read-only form.
- `resolveProviderPromptTools(providerId, agent?, { readOnly? })`: returns the shared, minimal provider/agent prompt-tool override. Copilot disables both OpenCode names for the optional Resend MCP namespace. Orchestrator disables provider-native `task` and the invalid placeholder while retaining installed plugin and MCP tools; writable managed children additionally disable provider-native delegation. Read-only managed tasks fail closed by disabling every tool and reopening only an explicit inspection allowlist, keeping custom or newly discovered mutation and delegation tools unavailable. Policies merge when applicable.
- `createManagedTaskResultEnvelope(task, options)`: creates a terminal parent handoff.
- `compactManagedOrchestrationState(state, options)`: applies durable count/age/byte policy.
- `assertManagedTaskTransition(previous, next)`: validates lifecycle and immutable identity.
