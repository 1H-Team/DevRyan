# scripts/qa/

Repository-only Electron/web QA and shared CDP inspection helpers. No file in this directory enters the shipped UI or changes native security policy.

- `run.mjs`: existing isolated QA entrypoint plus an explicit `--config` path to the separate matrix runner.
- `matrix-runner.mjs`: pinned actual-UI matrix lifecycle, private host/profile startup, served-entry verification, provider/model/agent/Plan/effort selection, core/project/compaction journeys, diagnostics, owned tree cleanup, and per-cell evidence. A fixture or partial compaction result does not establish live-provider or full continuity acceptance.
- `host-readiness.mjs`: bounded loopback readiness requests outside the renderer, including native packaged origin discovery; startup cannot strand a CDP evaluation.
- `initial-bootstrap.mjs`: first-cold-reload gate with a 180-second ceiling capped by the cell deadline. Requires initialized UI provider/agent state, usable visible controls, and the pinned model plus primary agent in the real native catalogs; bounded catalog reads preserve request timings and the last UI snapshot. Its read-only effective-selection projection also gates the exact current provider/model/native-agent after primary-agent selection and before effort selection or any send. Fixture cells additionally require the merged agent Low default and visibly selected Low before choosing the requested effort; the matrix independently verifies the standalone configuration-agent API pins. Ordinary reload and selection checks retain the UI driver's 30-second limit.
- `reasoning-controls-evidence.mjs`: whitelisted reasoning-control projection and per-user-turn native-hook grading; reports adapter defaults separately from the UI's explicit default selection and does not claim wire-level capture.
- `submitted-turn.mjs`: exact newly submitted human-text identity, canonical Plan-instruction verification, and fresh non-summary response selection, including native compaction continuations; generated user records cannot displace the actual UI input in acceptance evidence. A textual request to pause does not substitute for an enabled Plan toggle.
- `terminal-permission.mjs`: ends a QA turn only after two fresh idle snapshots of the same completed tool-call assistant, directly parented by the submitted human request, with a failed canonical tool and exact typed native permission rejection. Historical errors, unproven continuations and error prose cannot establish this terminal state; it never grants permission or resumes work.
- `packaged-artifact.mjs`: validates the QA package archive, shipped UI, and recorded unpacked SQLite/PTY binaries before and after Electron matrix cells; matrix Electron runs require `DEVRYAN_QA_PACKAGE_EVIDENCE` and prove the actual packaged host booted.
- `ui-driver.mjs`: bounded actual input and pointer actions, stable hit-tested controls, clipped-text visibility, attachments, reloads, and UI inspection. Native wheel reveal targets the exact control or text leaf and avoids converging under a covering sticky header; it does not write application stores. An explicit read-only disabled-target option accepts only a pointer-transparent disabled button whose center hits its own immediate parent; interactive click checks retain direct target ownership. Exact approval-button captures opt into full rectangle visibility inside the chat viewport, while existing broad reveal targets keep their prior center rule.
- `artifact-evidence.mjs`: source and built-file identity, drift detection, and bounded retention of tracked and added project files with original/archive hashes. Result serialization preserves only the screenshot callback's successfully written, safe relative PNG basenames after content sanitization; every other metadata field retains the shared sanitizer.
- `live.mjs`: explicit loopback live-provider HTTP smoke with password-free fixture login, owned session cleanup, and sanitized correlation evidence. Makes real provider requests only when invoked with an explicit origin.
- `cdp.mjs`: bounded CDP requests, target discovery, renderer evaluation and disconnect rejection; also reused by the existing packaged Electron resource benchmark.
- `process.mjs` / `process-ownership.mjs`: loopback port reservation, bounded child logs, graceful owned-parent shutdown, and retained OS PID/start-identity ancestry. Captures separately detached descendants while their owned ancestors exist, stops only matching recorded identities, and exposes final cleanup audits; snapshot gaps or surviving identities fail cleanup before profile removal. Does not discover or stop user processes by name, path, or port.
- `matrix-config.mjs`: separate opt-in strict matrix schema; pinned fixture/live selections, nullable provider-default effort, scenario/runtime constraints, bounded repetition expansion, and cache-contained evidence paths. Optional `projectCompaction: 'manual'` is restricted to live Electron project-work cells and preserves their run count. It does not change the existing QA or agent-eval defaults.
- `profile-preparation.mjs`: creates the live matrix's private managed profile from candidate defaults, copies installed dependencies and unexpired access credentials without refresh tokens, pins agent models, validates canonical cache paths and the fixture Git root, and records installed versions and file fingerprints. The profile APIs optionally accept explicit same-provider `agentAssignments` for known specialist roles without changing primary defaults; explicitly assigning a disabled specialist is rejected; `agentModels` and `agentSelections` retain the actual role model/variant map. This focused diagnostic option is not a matrix field and still requires live catalog/child/result verification. Before any live host starts, the matrix checks copied selected-provider OAuth/Claude expiry against its full cell timeout plus ten minutes; missing expiry or insufficient remaining access fails the cell. Existing OpenAI/xAI API-key support remains available with an explicit not-applicable expiry check and no credential-lifetime guarantee. Appends `provider-observer.mjs` through native OpenCode's final inline config merge.
- `isolated-home.mjs` / `isolated-host.mjs`: apply the owned private home before host/provider imports, launch the actual web or Electron runtime, and load the bounded private credential environment. The parent process environment and the user's live profile are not changed.
- `package-electron.mjs` / `packaged-host.mjs` / `packaged-host-policy.mjs`: build an unsigned macOS arm64 QA app with the actual bundled main, packaged server dependencies, preload and chosen web artifact. The test-only bootstrap validates its private profile before importing production main, suppresses global protocol registration, disables the private profile's background Bot service, and keeps login-shell configuration private. The packager verifies copied native versions and executable behavior plus packaged source/artifact hashes; it does not sign, publish, replace an installed app, or claim native updater acceptance.
- `project-fixture.mjs`: fresh dependency-free task-board Git repository, two seeded behavioral defects, domain/store/HTTP/browser layers, real PNG/text requirements, a preserved dirty user note, staged revision/approval prompts, and external hashed seed evidence. Cleanup checks exact run-owned directory identity.
- `acceptance-graders.mjs`: independent executable domain/API/restart probes and protected-file/plan-phase checks; reuses agent-eval causal tool and exact managed-task graders. Compaction grading requires observed boundaries from one explicit source, authoritative revisions/task state, and separately captured behavioral evidence. These functions do not establish browser acceptance or make model/provider requests.
- `project-browser.mjs`: separate owned Chromium shell for black-box inspection of the agent-edited task-board application, including persisted priorities, ordering, filtering, reference colors, mobile overflow, and keyboard focus.
- `project-compaction.mjs`: composes the existing two-boundary manual adapter into an opted-in Electron project-work run, preserving its project/session and pinned selection. Requires separate restored-summary/revised-state continuation evidence for each native boundary, operational continuity and independently graded implementation. The runner keeps seeded-failure, canonical task and browser grades; no extra scenario run is created.
- `provider-observer.mjs`: final native plugin observer for whitelisted reasoning options, model limits, canonical selection, compaction lifecycle, and session-error identity. It never changes provider options or records prompts, arbitrary error data, or credentials.
- `live-task-evidence.mjs`: bounded canonical message pagination and recursive child discovery through the authenticated UI API, sanitized causal repair evidence, and exact managed dispatch/child/disposition checks. Every project-work capture requires a strict native source-read → failed-test → source-mutation → passed-test chain with numeric exits and unchanged original tests/script. Reads and mutations must identify regular, non-symlink files under the owned src/public tree; Plan/README work and opaque execution cannot supply those source steps. Selected calls retain exact session/call identities. Builder remains root-only; Orchestrator permits the real root/child graph while independently requiring exact managed membership and dispositions. It never reads exit codes from prose. Orchestrator barrier clearance comes from the scheduler's read-only handoff inspection (`confirm: false`), not session idleness. Plan child policy checks correlate actual parent Plan turns with wildcard-denied canonical child prompt tool maps. Recursive cleanup reuses the evaluator's bounded abort helper and retains known children after partial capture failure.
- `fixture-scenarios.mjs`: credential-free private host profile and actual shared-UI fixture adapter for core/mobile cells. Pins native models, standalone configuration-agent sidecar overrides and private application defaults from one fixture selection with Low effort; actual UI input must still select and submit each requested Default/High value. Drives new-session attachments, empty/delayed reasoning, captured queue effort, permissions/questions, rejected sends, reconnect/cancel, draft retention and older-history anchoring. Synthetic compaction message records test Default/High selection restoration and saved Plan-card approval after reload: the driver must scroll the exact approval button into view, including the disabled historical source, and the actual submission must retain its exact source marker, saved path and thinking selection while leaving Plan mode. These cases do not establish native compaction acceptance. It uses `ui-driver.mjs` plus matrix evidence hooks; provider/scheduler and compaction acceptance require the live adapter.
- `fixture-failures.mjs`: drives exact permission denial/recovery, keyboard-readable failed and recovered tools, deliberately missing message/idle events followed by production reconnect snapshot recovery, and a measured ten-second idle interval before a fresh send. Failure records retain canonical call/message identities and distinguish suppressed fixture delivery from native-provider failures.
- `fixture-mobile-coverage.mjs`: actual touch, pointer, and keyboard verification across portrait/landscape/tablet in both themes. High-to-Default mobile choices must submit canonical explicit-empty effort and restore both the label and pressed state after reload. Separate desktop/mobile/desktop and session A/B/A routes must preserve an unsent Low choice against canonical Default, including actual raw and canonical submissions, before any managed-task fixture is installed. Rich scenes retain a saved Plan, expanded tool/reasoning, queue, running/completed task rows, exact child navigation, native selection overlays and permission replies. Saved-plan captures first reveal the exact Implement Plan button and record its fully visible bounds within the chat viewport without activating it. Settled coarse/fine sidebar checks verify first-character hit ownership, action spacing, hidden-anchor size and native target sizes. Coarse workspace headers in the landscape sidebar and actual phone/tablet drawers require every visible title glyph to retain hit ownership and every action target to remain separate; trusted Project Menu opening/closing must preserve the selected session, composer, drawer, dialogs and project expansion. This verifies shared browser UI; physical mobile keyboards and scheduler execution remain separate.
- `fixture-managed-tasks.mjs`: constructs deterministic managed-task read records through production record constructors, linked to exact canonical fixture child/message IDs. A pre-navigation script supplies only scoped loopback GET snapshot/task reads to the actual UI, forwards non-orchestration fetches unchanged, and rejects unknown routes or mutations while recording each request. Restore removes the script and returns captured fetch references to native forwarding. It never writes application stores or simulates scheduler actions.
- `compaction-scenarios.mjs`: live manual compaction adapter, also reused by opted-in Electron project composition. Pauses implementation, preserves two saved plan revisions, submits `/compact` through the composer twice, requires exact canonical summary linkage and independent native lifecycle observations, retains each boundary's restored-summary/paused-project continuation record, reloads the current plan, and continues through the actual approval surface in the same session. Orchestrator cells seed two marked read-only investigations, require the strict mixed cohort in snapshots wholly before and after the native compacting timestamp, collect/disposition those exact IDs once, and retain their completed identities through the second boundary. The earlier pre-request snapshot is retained separately and cannot establish native-start coverage. Builder cells require a nonempty baseline of observed source reads/native failed tests and reject exact repetitions during the pause. Natural thresholds and browser acceptance remain separate.
- `compaction-action-evidence.mjs`: sanitized canonical source-read/native-test/action-marker projection, call-ID merging across pruned context and independent operational continuity grades. Manual helpers default to the mixed cohort; natural phases explicitly select one active or completed-awaiting witness. Native-start brackets and nearest wholly-after-summary observations retain exact attempts, recovery lineage and unique pending envelopes. Post-summary collection requires the one canonical continue interval to bracket its acknowledgement. Natural grading checks both phases, retained earlier completed work, global dispatch/child/attempt/result identity and exactly-once collection across all sampled stages through implementation; first child binding is allowed, rebinding or later disappearance is not. Canonical action identity conflicts remain sticky. Builder grading remains exact source-read/test repetition during the pause, with independent implementation behavior required.
- `compaction-snapshot-evidence.mjs`: shared manual/natural snapshot recorder. Schema 2 interns immutable full task projections and stage labels while retaining every actual HTTP request/response interval in completion order. Its decoder maps legacy arrays or compact references to the unchanged temporal graders; no timestamps or missing reads are reconstructed. Hard projection/read/stage/byte limits set a sticky gap. Unavailable observations retain their exact windows. Only repeated action-count audit checkpoints coalesce; canonical actions and both polling schedules stay unchanged.
- `manual-compaction-submission.mjs`: reads the mounted Queue Messages by Default setting before live witnesses exist, types the completed `/compact ` command into the exact focused composer and uses one Ctrl+Enter (queue on) or Enter (queue off). Retains only exact-origin/session summarize request, response and bounded failure metadata with final cleanup. Request observation receives the existing 30-second UI action budget from the single key arm, capped by the cell deadline; the first matching request clears that timer, and response/native observation retains the original absolute cell deadline. The receipt distinguishes the request deadline and failure. HTTP acceptance remains separate from canonical summaries and native lifecycle gates. The desktop core fixture adapter exercises both queue modes across idle/busy transitions against the existing summarize 404, restores its private preference and rejects any abort, ordinary prompt or queued command. Its expected 404 proves command routing only, without synthetic native compaction.
- `compaction-approval.mjs`: pins revision 2 to its exact saved session revision in Plan mode, or the existing project plan file with Plan off. The Plan-mode reference retains the original human/source identities, session directory/creation/slug, raw path, bytes and hash; exact revision reads stay inside the prepared runtime's fixed project-plan directory, reject symlinks and require disk/API byte equality. Manual and natural adapters check the same reference at paused boundaries and before approval. Fresh Plan-card preparation asks through the real composer to read that existing file without changing it, requires a successful native read and a new canonical source reproducing the full saved body, and verifies the whole paused project remains unchanged. It cannot change the baseline to a later card or refeed the saved contents as the request; stale cards remain disabled.
- `natural-compaction-scenarios.mjs`: live Electron automatic compaction adapter. Derives the unchanged native threshold from pinned runtime policy/config/output cap/model limits and requires two automatic summaries with measured usage crossings and native lifecycle evidence. Preserves revised plans and paused files through steering/reload, approves implementation through the current UI surface and grades domain/API/restart behavior. Natural Orchestrator phases seed the existing bounded domain-review Oracle once near boundary one (active witness), then browser-location Explorer once near boundary two (completed-awaiting witness). Each phase records its exact native bracket, pending summary exit, reload, collection and Plan child policy; the earlier collected result remains through phase two. Each prefill shares the original workload bounds and observation start, excluding only the recorded prior boundary/events. Both post-seed workloads are input-only. Automatic collection stays enabled; unavailable witnesses fail without holding, recreating or inferring state. Builder source-read/native-test continuity remains unchanged; provider overflow, exhausted bounds and evidence gaps cannot substitute for acceptance.
- `compaction-retrieval-diagnostic.mjs`: three fresh Builder/Plan-off manual-compacted/control pairs using identical UI inputs and one ordinary audit batch. Records matched authoritative preconditions, exact pending-question correlation, canonical path/glob/read ordering, native manual boundaries, paused-file preservation and independent arm failures. Triage candidates require human classification; generated plan differences are retained, and no result establishes retention, automatic-continuation or natural-compaction acceptance.
- `browser-shell.cjs`: sandboxed test-only Chromium window for the web runtime.
- `*.test.mjs`: transport failure, argument validation and owned-process cleanup contracts, recursively discovered by `scripts/test-scripts.mjs`.

Commands, prerequisites, coverage limits and journal investigation: `docs/QA.md`. Deterministic provider transport: `../perf/loopback-opencode-fixture.mjs`.

- `recovery-cards.mjs`: opt-in `DEVRYAN_QA_SCENARIO=recovery` web/Electron replay of a failed dispatch, six attempts with removed ancestors, canonical child navigation, recovered Plan persistence, reload and narrow viewport acceptance. Also verifies generic Explorer/Designer titles summarize task briefs, persist after idle, and survive reload. Uses deterministic HTTP/SSE records and scoped task snapshots; it does not execute a live provider.
- `meridian-designer-continuity.mjs`: opt-in live control/candidate comparison using copied Meridian packages, one fixed Opus/high brief and cache-owned tools. Reuses OAuth in memory, isolates native session directories, bounds requests/time, and records acceptance, first edit, completion and session continuity without restarting the user's runtime.

- `thinking-slider.mjs`: opt-in `thinking` scenario, real shared-UI 0–5-stop
  catalog checks, pointer resistance and commit, touch cancellation, keyboard
  focus, light/dark/narrow screenshots, reduced motion, and native submission.
