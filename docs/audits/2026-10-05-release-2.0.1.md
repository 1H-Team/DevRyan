# DevRyan 2.0.1 release verification

2.0.1 is a launch hotfix for the macOS Apple silicon desktop app. Version 2.0.0
failed its first launch on upgraded installs with `native_setup_json_invalid`:
the one-time setup import parsed every file below
`~/.config/openchamber/projects/` as JSON, including saved version 1 plans
(`projects/<id>/plans/*.md`) and Finder `.DS_Store` files. The failed attempt
also left a half-seeded `~/.local/state/devryan/fresh-native-source` that a later
retry could refuse with `native_setup_seed_changed`.

## Changes

- The import reads only top-level `projects/*.json` records and skips Finder
  metadata in every copied folder. Version 1 plans and conversations are never
  imported and stay on disk.
- An abandoned, unpinned first seed is redone from current setup. Unselected,
  stale, unverifiable or interrupted runtime drafts are discarded before any
  selection exists; the fresh setup copy and drafts are renamed aside before
  removal, and leftovers are swept under the bootstrap lock.
- Benign setup content no longer blocks launch: in-HOME symlinks are followed,
  except into credential, token, browser and DevRyan secret stores or DevRyan
  state; VCS/dependency folders, oversized, unreadable or special files and
  unsupported `auth.json`/Meridian entries are skipped and summarised in one log
  line. Generated credential, Meridian and owner rows are pinned first and fail
  closed. Seed caps match the verifier. Failures carry a sanitised
  `relativePath`.
- Local owners are restored once under a lock whose reclaim proves pid reuse.
  The bootstrap lock waits for a live provisioning holder.
- Login-shell values that provisioning refuses, `DEVRYAN_RUNTIME_BUNDLE_ROOT`
  and, in packaged apps, development redirections are filtered by one predicate
  in both the Electron and the server login-shell merges.
- A background runtime from another app version is retired instead of reused.
- The prepared-draft snapshot excludes only the bundle database's wal-index.
- The confined native controller may delete exactly the one-time setup
  credential seed in its otherwise read-only configuration. Before, it imported
  the credentials and then failed with EPERM on every boot, so any upgraded
  install with saved provider sign-ins could never start the runtime.
- The Cursor SDK worker exports its ripgrep path to the SDK's ignore mapping in
  every mode.
- Releases publish only `DevRyan-<version>-arm64.dmg`; the verifier enforces the
  exact allowlist. Without updater metadata, the Update action drains the
  background runtime and opens the verified DMG download.

## Review process

The fix was developed in eight find, fix and independent re-verify rounds plus
a cross-group adversarial integration review. Each finding was reproduced by a
separate agent at the base commit, fixed with failing-first tests and replayed
against the fix. Reproductions are retained under
`.cache/v2-validation/r21-a2-*`, `r21-hotfix-reverify-*` and
`r21-hotfix-integration-*`; the A2 and integration findings are in
`.cache/v2-validation/r21-hotfix/{a2-findings,integration-findings}.json`.

## Local verification

- Real-setup dry run: `provisionDefaultNativeBundle` ran against a private APFS
  clone of only the owner's setup inputs with state redirected into the clone.
  The seed completed and `default-native` was prepared and selected; 8 project
  records, both local owners and the credential projection were imported; only
  608 version 1 plans and 10 Finder metadata files were skipped. The clone was
  removed; live files were read once and never written. Evidence:
  `.cache/v2-validation/r21-hotfix/a3-real-setup.json`.
- `bun run validate:full`, `bun run build`, `bun run bundle:check` and
  `bun run docs:validate` passed on the release candidate. Logs:
  `.cache/release-2.0.1/`.
- `bun scripts/build-native-runtime.mjs` passed with build ID
  `fde256263dd314f57074e588ba1572b25ab427b7ed24e5f24685da427b058837` and
  manifest SHA-256
  `4840024a98716ab290b46f2dcf4c963b25176d562daa0c1d6fea544af328872e`.
- Compiled package acceptance with `--reviewed-setup` passed all 80 cases with
  that artifact.
- Packaged first-launch smokes (`scripts/qa/first-launch-smoke.mjs`, QA package
  `.cache/qa/packaged-electron-KNKOzx`) passed all four scenarios, each reaching
  a ready native runtime with an unchanged version 1 source tree and no
  surviving process: an owner-shaped tree (608 plans, Finder metadata, fixture
  credentials); a half seed produced by the actual v2.0.0 importer followed by a
  settings change; a bundle selected by v2.0.0 with its shipped artifacts, which
  stays selected and is offered an explicit runtime update; and login-shell
  exports of refused variables, which are dropped and logged by name only.
- Real-setup boot: the owner's cloned setup with fake keys for the same five
  provider IDs provisioned, imported all five credentials, consumed the seed and
  reached a ready runtime from a Finder-shaped launch (`/`). The clone was
  removed. Evidence: `.cache/v2-validation/r21-hotfix/a3b-result.txt`.

The first two `validate:full` attempts failed and were corrected without
relaxing assertions: a new deterministic test used a forbidden `skip:` option
(now portable through `/bin/sh`), and a Cursor SDK test exposed that the worker
gave the SDK's ignore mapping no ripgrep path outside execution mode.

The first packaged smoke run failed every scenario with `native_process_failed`
after successful provisioning. Two independent investigations and a verifier
traced it to the controller's Seatbelt profile denying the deletion of the
imported credential seed, reproduced it outside Electron from a Finder-shaped
launch, and validated the fix. Earlier compiled and packaged acceptance used
prepared bundles without a seed, so the default upgrade path had not been
exercised end to end. The smoke runtime now also lives outside any Git work
tree; inside the repository, the native Git helper correctly refused the
repository root.

## Open after 2.0.1

Live-provider journeys, complete diagnostic journal qualification and the
performance comparison remain unqualified. Findings deferred to the 2.0.2
review: in-process startup Retry cannot re-run a failed bootstrap; retained
native artifact sets are never pruned; `OPENCODE_CONFIG_DIR` replaces rather
than layers the seed source; Electron and server roots diverge when only the
login shell sets `XDG_STATE_HOME` or `OPENCHAMBER_DATA_DIR`; required seed inputs
over 1 MiB; hard-link and same-uid path-swap limits of the seed deny-list; a
half-deleted fresh source left by a 2.0.0 in-place removal; a 2.0.0 owner
snapshot can restore a removed owner once; `.stale-*` drafts left after a
rollback; service-mode first launch is not covered by the packaged smoke; a
registered project that is not a Git root but lies inside an unregistered
parent repository can make the native Git helper refuse that parent; compiled
acceptance should boot a bundle with a seeded credential file; ZIP,
blockmap and `latest-mac.yml` are still built; the manual
`build-macos-arm64-dmg.yml` workflow can no longer package releases.

## Publication

Installed 2.0.0 and earlier apps cannot update in-app to 2.0.1 and need a
manual DMG install, as described in the changelog; 2.0.2 is also a manual
install. The `v2.0.1` tag defaults to `desktop-macos-arm64`; finalization
requires the signed Bot image manifest (internal), the packaged runtime gates,
the hosted migration/schema gates and exactly one public asset.
