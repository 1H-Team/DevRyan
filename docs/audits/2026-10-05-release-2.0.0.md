# DevRyan 2.0.0 release verification

The authorized distribution is the macOS Apple silicon Electron desktop app.
Web/npm, Intel macOS, Linux and Windows publication remain blocked until their
native runtime artifacts are qualified. The desktop release retains the signed
Bot image, packaged application, updater metadata and hosted migration gates.

  deterministic suites, including 4,042 UI tests and 6,165 web Vitest tests.
- `bun run build` and `bun run bundle:check` passed.
- `bun scripts/build-native-runtime.mjs` passed for `darwin-arm64` with build ID

  It covers bundle preparation/replay, reviewed command admission, native
  ownership, physical read/write, cancellation, publication, Undo/Redo,
  restart, migration rollback and independent supervisor termination.
- Electron web staging and fresh QA packaging passed with verified Electron
  41.2.1, SQLite 12.11.1 and node-pty 1.2.0-beta.12 native bindings. The QA shell

## Corrected and incomplete checks

Earlier compiled runs failed because the artifact lived beneath a directory
explicitly denied by the qualification sandbox, and because configured command
fixtures omitted primary admission outside reviewed setup. The final run uses
the isolated artifact and requires admission before creating a session. Failure
evidence was retained and assertions were not weakened.

The first draft CI run found two clean-checkout failures: a generic `data/`
ignore rule excluded the reviewed CSS parser's pinned `data/patch.json`, and
the CI adapter eagerly imported installed desktop runtime modules during image
planning. Reviewed input exceptions now follow the generic exclusions; runtime
packaging imports load only for their owning operations. Dependency-free image
planning and prepared-import identity refusal have regression coverage.
Full validation, production build and bundle checks passed again after these
corrections. All 1,368 reviewed input sizes and hashes match the pinned manifest;
every required input is committed or restored by the verified Claude hydrator.

The second draft exposed a fresh-launcher verification path that invoked
`node:test` hooks through Bun. The helper now selects Node for that verifier
when built by Bun. Its Revert fixture also still advertised the removed legacy
capability; it now advertises `conversationOnlyRevert: 1`, retains both original
file-content assertions, binds the worker to the test's cancellation signal and
awaits cancellation/settlement in `finally`. A fresh Bun-driven helper build
passed the complete 15-probe native suite and only then set `acceptance: true`.
The failed fixture's retained evidence reports `mutation_runtime_unsupported`;
no production guard was relaxed. The isolated failed fixture processes were
terminated, and no fresh-launcher process remained.

Compiled package acceptance also passed all 80 cases for the Node-runner
correction (build ID
`28860c82e1851ea43506d3e487439bf86daf37feb8e505573a61d44b93249c95`,
result `.cache/v2-validation/package-wKOtLJ/result.json`). The subsequent Revert
fixture correction changes build provenance without changing native runtime
logic; the rebuilt current artifact has build ID
`d3fe4b428afbcbdcbf2af774c9faf006ada938955abfc713e393bb8002cfd59d` and
manifest SHA-256
`cf7089dc820760cef2fee20913df75de3f12528515799cc63bc8f829e5da65bd`.
Its additional acceptance evidence is retained under
`.cache/release-2.0.0/native-package-qualified.log`: all 80 cases passed with no
cleanup failures, with result
`.cache/v2-validation/package-hTctYV/result.json`. Full validation, production
build, bundle checks and documentation validation also passed after the launcher
corrections.

Legacy web QA depends on external OpenCode launch settings that the native v2
runtime rejects. The current native matrix replaces that incompatible harness.
Two initial wire cells lacked an explicit native artifact path; one later core
cell detected a script edit during its run. The final desktop core rerun passed
with frozen source and explicit native artifact configuration.

The full mobile web fixture journey failed its final return to the original
session after its individual responsive and recovery assertions had passed.
Mobile web acceptance is therefore incomplete. Evidence remains in
`.cache/release-2.0.0/ui-wire-rerun/web-mobile-fixture-mobile-1/`.

Live provider parity, complete diagnostic journal qualification and the broader
performance acceptance work remain unqualified, as recorded in the v2 upgrade
handoff. Synthetic credential/provider fixtures do not establish live provider
success. Local ad-hoc native signatures do not establish release signing or
notarization. Those production artifact gates must be established by CI before
publication; no performance improvement claim is made.

## Publication gates

After committing and pushing, run the existing hosted Supabase migration
workflow against `main`. It lists pending migrations, applies them and verifies
`public.devryan_bot_schema_version()`; the current expected marker is
`20260908182901`. No new SQL migration was introduced by the pending change set.

The `v2.0.0` tag defaults to `desktop-macos-arm64`. Finalization requires the
complete signed Bot image manifest, branded DMG/ZIP/blockmaps, `latest-mac.yml`,
packaged runtime verification and hosted schema verification. Universal web
packaging still refuses missing platform artifacts. Release announcements
require a separate explicit manual input.
