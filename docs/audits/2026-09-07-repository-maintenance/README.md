# Repository maintenance audit — 2026-09-07

## Basis and scope

This pass applies Eric Provencher's [instruction-maintenance article](https://x.com/pvncher/status/2095991462416490862): contextual guidance, concise discovery descriptions, explicit completion, and preserved decision boundaries. The article was read in the browser. Repository files, manifests, tests and runtime contracts remain the implementation authority.

[inventory.csv](inventory.csv) accounts for repository-owned tests, Markdown/MDX, agent instructions/prompts, skills, package/Cargo manifests and lockfiles. It excludes generated output, dependencies and this report's own evidence directory. Each row records its category, source hash, disposition and review basis. Static test signals are navigation aids, not proofs of isolation or coverage. All deterministic suites were executed; deeper assertion and documentation review focused on the findings below. Passing tests do not establish untested live-provider or platform behavior.

## Findings and changes

| Finding | Resolution |
| --- | --- |
| Root instructions required large document reads before every task and contradicted scoped validation | Reduced AGENTS.md to repository invariants and contextual links. Preserved detailed UI/sync and operational rules in dedicated runbooks. |
| A mandatory CLI skill name was unavailable in the session | Core parity policy is now self-contained; the optional skill can supplement presentation when available. |
| Explorer's fixed search-pass ceiling could truncate an explicit full usage map | Both local and packaged Explorer descriptions/workflow are shorter and scope-based. Permission frontmatter, models, output markers and runtime recovery contracts are preserved. |
| Browser skill claimed all tabs shared one cookie partition | Corrected ordinary agent, branch-preview, and manual partition distinctions; retained login-state and cleanup safeguards. |
| Documentation validation checked only seven site pages | Added repository local-link/source-reference validation and behavioral parser/fixture tests. Historical and generated targets are explicitly reported. |
| Packaged Markdown prompts could bypass tests as documentation-only | Quick/affected planning now selects the owning runtime contract suite; project prompts/plugins select repository script tests, and project runtime configuration selects the full gate. |
| Shared-runtime changes had no scoped test owner | Added shared-runtime tests and affected web checks. |
| Nested manifests/lockfiles could receive only package checks | Full validation is selected; test-only affected mode selects the full deterministic suite. |
| Release smoke checked exact shell source strings | Replaced it with execution of the actual script against disposable tool doubles, asserting signed/unsigned/no-bundle command arguments. |
| PR and standalone macOS CI used Node 20 below the declared engine floor | Updated those jobs to Node 24; existing Node 22 release jobs remain valid. PR checks now include documentation validation. |
| Public installation/theme docs referenced upstream, stale branding or Node requirements | Corrected DevRyan source/release locations, compatibility-command explanation, supported surfaces and Node floor. Corrected stale skills-install paths and task-specific codemap wording. |
| Docs workflow defaulted to an upstream website dispatch | Optional dispatch requires `DEVRYAN_DOCS_WEBSITE_REPO` plus the existing compatibility-named token secret. No deployment or dispatch was performed. |

The full-suite discovery, permission, signed-artifact, Plan authority, managed-scheduler, recovery and cross-runtime gates remain present. Source-text assertions remain where the delivered text/configuration is itself the contract; the release argument test was replaced because actual execution offers stronger evidence. No duplicate test files were found by content hash. No deterministic behavior was removed or silenced with skip/todo.

## Dependencies

[dependency-audit.json](dependency-audit.json) records every declared external dependency, registry candidate, final declaration and disposition. [release-metadata.json](release-metadata.json) records version-specific registry metadata for changed resolved direct dependencies, including engine and peer constraints.

Compatible range floors were aligned across five manifests; the Bun lockfile was refreshed and the existing ghostty patch reapplied. No new direct dependencies were introduced. The bot-indexer npm lockfile remains paired with its unchanged exact SQLite dependency; the locked Tauri Cargo graph is unchanged.

Intentional constraints retained:

- CodeMirror language/state/view overrides remain a coordinated set; this pass does not replace their known rendering baseline.
- Ghostty 0.3.0 retains its local patch; 0.4 is a separate pre-1.0 compatibility change. `@pierre/diffs` retains its beta pin.
- Electron 41.2.1, Cursor SDK 1.0.28, MCP SDK 1.29.0, exact document/auth/runtime packages and TypeScript's tilde range remain pinned. Their native/API/provisioning contracts need dedicated upgrade evidence, not a presumed compatible version bump.
- Canonical and legacy bundled-profile versions intentionally differ. Their provisioning/loader contracts were retained, not synchronized blindly.
- electron-builder uses the stable latest tag 26.15.3 rather than the higher untagged registry candidate. The initial install reported an optional Windows Squirrel peer at 26.8.1; the final lock still retains it. This audit does not establish Windows packaging compatibility.
- Major migrations (including Vite 8, TypeScript 7, ESLint 10, OpenAI SDK 7, HTTP proxy middleware 4 and Electron 44) are reported by the registry inventory, not applied.

Primary release notes reviewed include [Base UI 1.8](https://base-ui.com/react/overview/releases/v1-8-0), [React 19.2.8](https://github.com/react/react/releases/tag/v19.2.8), [Zustand 5.0.15](https://github.com/pmndrs/zustand/releases/tag/v5.0.15), [Zod 4.5.4](https://github.com/colinhacks/zod/releases/tag/v4.5.4), and [DOMPurify 3.4.15](https://github.com/cure53/DOMPurify/releases/tag/3.4.15). ## Verification

The initial full validation baseline passed with the original dependencies and tests. Intermediate runs identified two assertions encoding the old validation/search policy; they were updated to the new contracts without weakening unrelated checks.

- Full build and startup bundle budgets passed. Startup gzip is 1,372,662 bytes against a 1,456,388-byte ceiling.
- A local web package was packed and extracted under the ignored audit cache. Default-config SHA verification passed, followed by the packaged configuration smoke for 16 runtime plugins.
- Focused prompt/skill provisioning tests passed (57 tests); the skill frontmatter validator passed. The final scoped-validation/parser checks passed.
- Web and Electron chat fixtures each passed six UI checks. Mobile web passed 16 checks across light/dark themes and portrait/landscape/tablet sizes. All 11 captured PNGs were visually reviewed. [UI results and screenshot paths](ui-verification.json) record each check; [web](visual/web/chat-idle.png) and [Electron](visual/electron/chat-idle.png) show the final chat states. Every QA run reported empty cleanup errors.
- Final `bun run validate:full` passed: workspace lint/type checks, documentation references, all deterministic package suites, and the locked Cargo suite. The web runner reports 359 files / 3,718 tests passed. After the last project-config routing addition, focused planner/parser checks also passed.
- `bun install --frozen-lockfile` passed with no package changes and reapplied ghostty successfully. `git diff --check` passed. Explorer frontmatter comparisons confirm unchanged permissions, models and runtime metadata apart from descriptions.

Unavailable/not performed: signed Electron/Tauri release packaging, notarization/updater installation, Intel/Windows execution, Docker service acceptance, live-provider/OAuth and hosted multi-user/database checks. This task neither releases nor deploys the application. Development Electron and the npm artifact smoke do not establish signed/native release acceptance.

Known nonblocking output: a Node `util._extend` deprecation in test dependencies, Rollup's removal of a misplaced purity annotation in Zod, and the optional Windows peer noted above. Historical/generated documentation warnings remain visible rather than being described as validated files.
