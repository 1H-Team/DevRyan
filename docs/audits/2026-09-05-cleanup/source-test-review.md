# Coding Agents source-test review

The Coding Agents portion of F08 is reviewed. The result is a small removal of duplicate source assertions and retention of the remaining contracts. This review does not claim that source matching proves runtime behavior or that every UI test has been converted. Bots tests remain outside this acceptance scope.

| File / assertion group | Decision and reason |
|---|---|
| `DesktopBrowserPane.test.ts`: capability, native ownership and host routing | Retain. These inspect caller wiring across the header, actions, browser runtime and native surface. URL/policy helper tests do not prove that the shell uses those helpers or selects the correct transport. |
| `DesktopBrowserPane.test.ts`: occupancy, mounted views, detached workspace, origin/auth identity, versioned messages and opaque URLs | Retain. The checks protect separate lifecycle and trust-boundary wiring. The current attachment/dialog/quit journey does not exercise all browser detach, logout and redirected-origin combinations, so it cannot replace them. |
| `DesktopBrowserPane.test.ts`: toolbar, typography, loading/error copy, diagnostics and layout classes | Retain with an explicit limitation: these check source structure, not measured geometry or interaction. No equivalent coverage for every browser state was established by this Coding Agents pass. |
| `ManagedTaskList.test.tsx`: task projection, recovery, terminal/error disposition, fallback identity, grouping and child navigation | Retain. Most assertions run real render functions or projection/navigation contracts. String assertions against rendered HTML are not source-text tests. They distinguish failed, recovering, queued, running and completed task records, including missing child identities. |
| `ManagedTaskList.test.tsx`: repeated card-border source checks | Remove three assertions from the mobile source test: the border class, color custom property and prohibited inset-shadow border. The existing `renders five same-turn task rows across two agents inside one Agent Dispatch card` test renders the real list and checks those same three properties on its HTML, together with one card and five child rows. Keep that rendered test and the distinct mobile width/stylesheet checks. |
| `ManagedTaskList.test.tsx`: message-owner placement, reasoning visibility independence, dispatch reconciliation and mobile/header wiring | Retain. Projection helpers alone do not prove that MessageList and MessageBody pass the correct owner, call identities and snapshot recovery flags. The remaining mobile stylesheet selectors and heading layout checks cover different obligations from the rendered border assertions. |
| `SessionNodeItem.test.ts`: tree-expansion and middle-button policy helpers | Retain the executed helper cases. Archived structural ancestors, permanent delete and ordinary archive have deliberately different outcomes. |
| `SessionNodeItem.test.ts`: exact-task/notification subscriptions, recovery, agent precedence and memo signature | Retain. They catch broad-store subscriptions and incorrect caller selection that pure selector tests cannot establish. Performance benchmarks supplement these checks; they do not prove all subscription wiring. |
| `SessionNodeItem.test.ts`: hover/swipe actions, leading rail, animation nesting, empty-state timing and export coordination | Retain. These include distinct ordering and lifecycle contracts. Native attachment/quit checks do not cover session export cancellation or destination selection while preparation is in flight. Mobile row geometry is separately evaluated in F14. |
| `mobileRightSidebar.test.ts`: chat tabs, drawer owner and drag-lock wiring | Retain the Coding Agents checks. They verify reuse of the shared drawer and that row swipes do not also drag the drawer. Viewport screenshots alone are not equivalent regression coverage for this wiring. The unrelated Bot assertion is untouched. |

Validation after the three-assertion removal: all 51 ManagedTaskList tests and four existing timeline-controller tests pass (55 total, zero failures). The removed assertions had identical obligations already checked against real rendered output; no test, policy guard, lifecycle case or dependency was removed. Full validation and final mobile/native evidence belong to the acceptance report.
