# Reusable cleanup, performance and QA audit

1. Read repository authority, codemaps and module docs. Agree runtime/repository boundaries. Inventory packages, source/tests, owned instructions/skills, shipped assets and dynamic adapters. Keep personal configuration separate.
2. Record HEAD, dirty state and content hashes for measured files. Isolate concurrent work before attributing regressions. Record existing full-gate failures, elapsed times, build warnings and startup bundle bytes.
3. Maintain one findings register: location, evidence, impact, proposed change, verification and fix/retain/defer disposition. A grep hit, file size or wrapper count is a lead, not proof.
4. For a test deletion, name its protected behavior and equivalent remaining coverage or obsolescence evidence. Use a temporary deliberate fault for disputed value, run the test, and restore exactly the changed bytes. Do not build a mutation framework or target a deletion count.
5. For an abstraction, inspect public imports, adapters, dynamic loading and package defaults before declaring it unused. Prefer one cohesive behavior-preserving batch; update discovery/matrix/docs/maps together.
6. Declare each performance metric first. Keep fixtures, builds, runtime versions, windows, display/visibility, warmup and duration identical. Run at least three fresh baseline and three candidate processes. Preserve raw samples, medians, variability, absolute and relative results. Do not extrapolate reducer timing to app latency or loosen budgets to make results green.
7. Verify typing/send during streaming, one/four sessions, history/open/switch/older-page scroll, expansion, abort/reconnect/idle recovery, startup and closed-session memory. Reject event loss, rich-field erasure, optimistic leaks and scroll jumps even when faster.
8. Launch actual hosts with private fixture data/profile/workspace roots. Print inspection endpoints, capture bounded sanitized logs, timing, screenshots, revision and exact correlation IDs. Retain OS ancestry plus process start identities while owned parents are alive; stop only matching owned identities, independently verify their absence, and retain evidence on failure. Reuse installed tools.
9. Resolve Error Log UUIDs through authenticated detail APIs before journal queries. Query session plus call/tool/message/task IDs, then check gaps and health. Missing/expired/gapped evidence qualifies conclusions.
10. Execute deterministic and configured live-provider journeys separately. Check responsive portrait/landscape/tablet in both themes, touch drawers, focus, controls and composer reachability. Inspect every screenshot. State physical-device keyboard and packaged native coverage explicitly.
11. Run focused checks per batch, affected-package checks for shared changes, then the required full gate, builds and bundle checks. Do not remove safety/packaging tests merely because they inspect source.
12. Deliver a concise report with reviewed evidence, measured claims, package/category dispositions and explicit unavailable checks. Never label the pass complete while required runtime or provider acceptance remains unresolved. Keep publication/deployment outside an audit unless authorized.

For coding-agent acceptance, freeze the configured provider/model set and cross it with primary roles, an orthogonal Plan flag, runtime and Default/explicit effort. Give every selection cell real multi-file work, independent failing/passing checks, requirements in attachments, mid-task steering and preserved user edits. Keep application graders outside agent-editable files and record actual child dispatch/result/disposition identities. A transport-only chat does not establish coding or planning acceptance.

Before broad live-provider matrix execution, complete representative manual and natural compaction journeys. Each must pass two verified native boundaries, resume implementation, pass the independent application and browser checks, and reconcile managed tasks, results and dispositions.

Test native continuity before adding memory. Require two actual boundaries, unchanged production thresholds for natural compaction, the current plan's original path/hash and paused implementation state, plus subsequent correct actions. For an orchestrator boundary, distinguish a running child from a completed result awaiting disposition; do not manufacture the lifecycle. Preserve failed prerequisites and gaps. Investigate suspected loss with three fresh matched compacted/control pairs, keeping source, profile, inputs and policy identical and retaining differing generated plans. Repair authoritative records or retrieval first; add bounded continuity or session memory only when the evidence requires it. Never use a recap, persisted UI card or missing glob result as proof of retention or data loss.

For a QA-only failure, make at most one focused correction and retain a separately identified retry. If the same objective fails again through QA machinery, stop expanding the harness: use an existing simpler direct route or report the requirement unverified. A passing supplemental check never changes the failed original outcome. Keep every scenario bounded; an unobserved natural compaction boundary remains unverified without changing production thresholds.

Before removing a private profile, preserve the journal, whitelisted provider observations, sanitized host/native logs, saved revisions, project changes and original/archive file hashes. Require an independent OS snapshot to show no retained PID/start identity still running. Treat snapshot failures as incomplete cleanup, not proof of absence. Never kill by executable name, port or a recycled process group. Do not delete a user's application, profile, worktree or credential source.
