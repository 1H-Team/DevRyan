# DevRyan agents on OpenCode 2 — upgrade and harness plan (revised after reconciliation with Codex)

Historical collaborative plan. The [verified finish plan](./OPENCODE_V2_AGENT_UPGRADE_PLAN.md) supersedes its execution order and readiness claims. Spike results below are not integrated production acceptance.

## Context

DevRyan runs its agents on OpenCode 1.18.33 through a source-patched build (the "companion", 42 files). OpenCode 2 is a different runtime: new server API, new plugin API, new storage, and no `packages/opencode` tree, so the patch cannot be rebased.

Decisions you already made (in this session and the Codex session): prefer native v2 with behaviour changes called out; lint/typecheck/compiler commands replace LSP; live QA uses your saved Astra-led graph; agents only, Bots untouched.

**Pin:** `@opencode/*` **2.0.20 exact** (tag `v2.0.20`, `84c9be93`). Floor 2.0.19, the first release without the session id in `<env>`.

**What "v2 prep already done" turned out to be:** nothing targets OpenCode 2. The `@opencode-ai/sdk/v2` imports are the 1.x SDK's second client, "companion 2.x" is DevRyan's own version number, and the v2 engine inside 1.18.33 is deliberately fenced off. Reusable pieces: the host/Bot pin split, the route guard, the degraded plain-runtime fallback, the separate `opencode-devryan.db`.

Evidence labels: **[V]** read at the pinned tag or in the repo; **[G]** unproven at runtime, so it is a phase gate.

## What breaks on a v2 runtime [V]

| Area | Fact |
| --- | --- |
| Launch | `--log-level` gone; readiness line and `/global/health` gone (`/api/info`); API is `/api/*` only, colliding with the proxy's `^/api` strip |
| Plugins | V1 plugins are rejected; configured file paths and `.mjs` are dropped; failures only warn |
| Config | `OPENCODE_CONFIG_DIR` **replaces** `~/.config/opencode`; project config loads **after** it (a repo can override DevRyan rules); config content is the final entry; one legacy frontmatter key sends an agent file through the V1 decoder and drops `permissions` |
| Agents | the primary runner uses `session.model`, not `agent.model`; agent temperature is inert; `AgentEditor.update` is an upsert — an unknown id starts from an allow-all default |
| Tools | `bash→shell`, `task→subagent`, `apply_patch→patch`, `filePath→path`; `todowrite` and LSP tools gone; plugin and MCP tools default to Code Mode |
| Storage | migration is in place and one-way; a stock v2 binary opens `opencode.db`, not `opencode-devryan.db`; credentials move to SQL after a one-time `auth.json` import; event payloads are not persisted by default, so the session log replays nothing |
| Events | `message.*` events gone (steps, text/tool events, forms replace them); messages have no `parentID`; SSE heartbeat is a comment |

## Architecture: a DevRyan runtime host, no core fork

Replace the patched binary with a **DevRyan-owned Bun entry that embeds unmodified `@opencode/sdk/effect`** and decorates core services through `OpenCode.create(options, { overrides })` and `node.mapLayer`. [V: types and source; G1: runtime]

Why not plugin-only: a throwing transform disables the plugin and the registry rebuilds without it, a later plugin can replace a wrapped `execute`, config can remove plugins with `-id` patterns, and hooks can reroute a call after admission. All fail open. [V: `core/src/state.ts`, `tool.ts`]

**Mandatory gates live in service decorators, outside the removable plugin registry.** Host-side ledger, receipts, cancellation generations and the native supervisor stay as they are.

1. **Tool gate.** Decorate `Tool.node` with a sealed editor: every `add`/`update` gets its `execute` wrapped after hooks and alias resolution, and each snapshot is checked against the current generation. `shell`/`edit`/`write`/`patch` go to the confined worker; `read`/`glob`/`grep`/`skill` keep direct receipts; non-allowlisted plugin tools are denied or run in a worker. Gate unreachable means `Tool.Error`.
2. **Code Mode off.** Constant `execute` deny in the snapshot rules and the final config content. Nested calls share the outer call id, `fetch` inside it is unpermissioned, and declines become catchable. [V] Every required plugin and MCP tool is explicitly `codemode:false`, otherwise it disappears while `execute` is denied.
3. **Session gate.** Decorate `Session` and `SessionExecution`: prompt, compact, synthetic, skill, shell, command, fork, move, remove (reserve the whole subtree), all revert operations, `wake`, `resume`, `interrupt({resume})`. Prompt (including plugin-originated and command-derived prompts) and manual compact auto-commit a staged revert, so they are fenced, not just the revert routes; automatic compaction does not. [V: `session/session.ts:165,252`] Commit also deletes every inbox item admitted after the boundary, so while a revert is staged the gate parks admissions instead of letting them be lost, and it serialises prompt admission with revert transactions to close the race where a prompt begun before Redo commits afterwards. Subagent completions are held before inbox admission until publication is durable; durable publication before wake is unchanged.
4. **Shell.** Decorate `Shell.create` and `Environment.spawner` so the user-shell route is confined and correlated to a call.
5. **Revert.** `snapshots:false` in the final config content, coordinator stages `files:false` only, ledger file evidence is the only file authority. With snapshots off, native restore fails explicitly. Do not substitute a no-op snapshot layer (restore would appear to succeed). Any existing file-restoring stage is reconciled **before** the policy activates, because a restage or clear can still restore files.
6. **Config authority.** The final config content carries the deny tail, `default_agent` and `snapshots:false`. Instance plugins are used for boot ordering only; they are not authority. Startup and `agent.updated`/`plugin.updated` assert the loaded agent and plugin catalog and refuse prompts on mismatch.
7. **Storage.** `events.persist:false`. Recovery uses projections plus the host's durable reservations, receipts and continuations. No log-follow dependency. Add replay storage only if a demonstrated feature needs it and has a retention proof.

**If G1 exposes a gap decoration cannot reach:** keep the embed design and add a narrow, reviewed seam for that proved gap only.

A degraded (unconfined) mode of the same host keeps today's behaviour on platforms without the native supervisor.
