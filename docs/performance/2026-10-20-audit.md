- Baseline-versus-baseline calibration starts at five pairs, expands to ten,
  then fifteen. `audit-statistics.mjs` resamples entire paired differences

  Working set median/p95: `max(5%, 16 MiB)`. The existing interactive workload
  and its two 180-turn histories remain unchanged; no 1,000-turn workload is
  introduced without a measured scaling bottleneck.
- Reducer comparison retains ten pairs and its existing MAD/noise rules. Its

## Isolation and host admission

The harness repair is its own commit, `c4e0f580`, before measurement. An
unforgeable constructor-owned scope tied to the canonical run directory's
device/inode is passed through fixtures and native preparation. Artifact
verification remains repository-owned. Replaced roots, symlinks and escaped
paths are rejected. Cleanup covers success, failure and interruption.

Historical checkouts are detached worktrees beneath one canonical OS-temp
audit root. Project fixtures are sibling directories, outside the checkouts.
Dependencies use APFS/reflink copies where supported, retain relative workspace
links, reconcile against each frozen lockfile without install scripts, and are
checked for links escaping their arm. Native rebuilds belong to each arm.

Before and after every runtime invocation, `audit-isolation.mjs` hashes content,
names and metadata of the real OpenCode, DevRyan and legacy configuration roots,
following compatibility links. Only hashes and metadata are persisted. Any
change stops affected testing; there is no automatic restoration over user data.
Runner HOME, XDG paths, temporary paths and runtime/browser/provider profiles
are private. Fixtures use synthetic credentials; paid-provider spend is zero
until an explicitly recorded bounded request is made.

Every audit agent acknowledged idle before each measurement window. No audit
build, install, test, analysis or live-provider work runs concurrently. The
user's app is never stopped. One-second OS observations retain its process-tree
CPU, other-host CPU and load averages. Before calibration the contamination
limits are fixed at two consecutive samples above either 25% of all logical
CPU capacity in unrelated processes or 50% of one core in the user's app tree.
Cumulative `ps` CPU-time differences supply interval CPU; lifetime `%CPU` is
retained separately. Exited-process CPU between observations is unavailable. The scanner recognizes
DevRyan/OpenChamber executable basenames; no such user-app tree was found in
these windows, so its reported zero is limited to that identification method.
Both arms use the same admission rule and rejected windows remain evidence.

## Experiments and selected fixes

No production performance fix was selected. The ten-pair reducer comparison
passed all 12 existing scenarios, with byte-identical reducer sources at both
historical revisions. That supports **no meaningful change** for this reducer,
not a rendering, sending or startup claim. No other journey produced valid
historical evidence from which to select a fix. Neither 150 ms timer nor history
caching was changed; ownership and publication checks remain intact.

Both historical web builds and arm-owned native-module rebuilds passed. An
identical QA-only packager overlay uses each arm's Electron framework and native
modules as its unsigned development donor; it preserves version, architecture,
manifest and executable checks. The historical baseline native build had two
unsuccessful attempts: a mismatched reviewed Claude input, then launcher
acceptance failure from AF_UNIX socket path length after the pinned input was
corrected. The experiment stopped. The candidate built successfully with a short
private TMPDIR and passed packaged SQLite/PTy smoke checks. Its binary was never
substituted for the missing baseline binary.

A candidate-versus-itself startup protocol check stopped after two pre-composer
`qa_native_input_path_invalid` failures. Its window was also contaminated by
unrelated host CPU. It is not the required historical baseline calibration;
there are zero valid paired startup observations and no startup confidence
interval or frozen comparison sample count. The missing preparation-factory
scope was then fixed with focused coverage, without a third calibration attempt.

The first candidate-only 180-turn interactive functional smoke failed before
Electron launch: direct fixture setup used an unauthenticated v1 path against
the authenticated v2 fixture. Preparation also left the fixture server open on
that error. The owned runner was interrupted with SIGINT after process ancestry
and checkout ownership were verified. Fixture authentication/routes and failure
cleanup now have deterministic tests, including a child-process exit deadline.
No diagnostic journal existed because the app had not launched; journal detail
and gap checks were unavailable. The second functional attempt stopped before
fixture launch because the isolated
launcher omitted the required `QA_NATIVE_ARTIFACT_ROOT`. It exited normally
with a failure status, passed host admission, and left real configuration hashes
unchanged. No third attempt was made. This launcher omission is an audit error,
not evidence of an application regression.
Neither a short functional smoke nor a contaminated window qualifies resource
or latency thresholds. The existing two 180-turn histories remain unchanged;
no 1,000-turn fixture or speculative application optimisation was added.

A final cleanup review also found that post-launch teardown closed only the
wire fixture, leaving its native profile/facade handles open. Teardown now closes
the complete profile before the second process audit, and does not overwrite
its completion verdict. A child-process test requires fixture, native-provider
and facade listeners all to close before the process can exit. This received
deterministic coverage only; the stopped runtime experiment was not retried.

The runner now has a bounded deadline, SIGINT cleanup grace and explicit forced
exit qualification. Lifecycle effects in migration tests use injected keychain,
launchd, updater and app owners. These changes repair correctness and measurement
infrastructure; they are not claimed as measured performance improvements.
